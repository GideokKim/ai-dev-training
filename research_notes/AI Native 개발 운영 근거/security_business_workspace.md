# Security, Business Workspace, and Codex Data Boundaries

조사 기준일: 2026-09-25. STEP 03 §§43–44 범위의 보안·워크스페이스 근거 노트다. 아래 내용은 OpenAI 공식 문서와 정책성 Help Center 문서를 기준으로 한 제품·정책 사실이며, 회사가 어떤 코드·데이터를 ChatGPT/Codex에 넣어도 된다는 허용 판단이 아니다. 회사 내부 보안, 데이터 분류, 고객 계약, 비밀정보, 소스코드 사용 정책은 OQ-014로 남긴다.

## ChatGPT Business/Enterprise와 Codex 데이터가 모델 학습에 쓰이는가?

### Takeaway

ChatGPT Business/Enterprise/Edu 및 API의 입력·출력은 기본적으로 OpenAI 모델 학습에 사용되지 않는다고 공식 문서가 설명한다. 개인용 ChatGPT/Codex와 Business/Enterprise/Edu는 데이터 사용 기본값이 다르며, Codex full-environment 관련 별도 controls가 언급되므로 plan/account/workspace를 반드시 구분해야 한다.

### Cited Findings

- OpenAI Business data privacy page는 ChatGPT Enterprise, ChatGPT Business, ChatGPT Edu, ChatGPT for Healthcare, ChatGPT for Teachers, API Platform의 inputs/outputs를 기본적으로 model training 또는 model improvement에 사용하지 않는다고 설명한다. Scope는 business products 및 API platform이고, page는 business data ownership, encryption, retention controls도 함께 설명한다. Confidence: HIGH. Volatility: MEDIUM, policy page와 product names may update. — [Business data privacy, security, and compliance](https://openai.com/business-data/)
- OpenAI Enterprise privacy page는 2026-01-08 updated로 표시되며, business data를 기본적으로 model training에 사용하지 않고, customer가 data retention과 internal source connection을 통제한다고 설명한다. Scope는 ChatGPT Business, ChatGPT Enterprise, ChatGPT for Healthcare, ChatGPT Edu, ChatGPT for Teachers, API Platform. Confidence: HIGH. Volatility: MEDIUM. — [Enterprise privacy at OpenAI](https://openai.com/enterprise-privacy/)
- “How your data is used to improve model performance” Help Center article은 개인용 ChatGPT와 Codex에서는 content가 training에 사용될 수 있고 opt out이 가능하다고 설명한다. 같은 문서는 business users, including ChatGPT Business, ChatGPT Enterprise, API의 inputs/outputs는 기본적으로 training에 사용하지 않는다고 구분한다. 또한 ChatGPT data controls가 full-environment Codex settings에 영향을 주지 않을 수 있고, Codex에는 full environments training controls가 별도로 있다고 명시한다. Updated: 2026-09-25 조회 시 “5 hours ago”로 표시. Confidence: HIGH. Volatility: HIGH for UI/control location. — [How your data is used to improve model performance](https://help.openai.com/en/articles/5722486-how-your-data-is-used-to-improve-model-performance)
- “Using Codex with your ChatGPT plan” Help Center의 localized article은 Business/Enterprise/Edu에 대해 business-user products의 inputs/outputs를 기본적으로 model improvement에 사용하지 않는다고 설명하고, ChatGPT training data controls가 Codex 처리 content에도 적용된다고 설명한다. 같은 article은 local workflows가 user device에서 실행되고 cloud tasks가 OpenAI-managed environment에서 실행된다고 구분한다. Scope는 plan-level Codex use guidance이며 localized pages may differ. Confidence: MEDIUM-HIGH because English canonical page was not surfaced in search, but content is OpenAI Help Center. Volatility: HIGH. — [Using Codex with your ChatGPT plan, zh-Hans](https://help.openai.com/zh-hans-cn/articles/11369540-using-codex-with-your-chatgpt-plan)
- HIPAA configuration guide for Codex states: “OpenAI doesn’t train on ChatGPT Enterprise data or Codex data.” It also states ChatGPT Enterprise stores inputs/outputs in OpenAI cloud, local Codex user workstations keep inputs/outputs, Codex sends prompts/files to OpenAI for inference, and OpenAI returns outputs. Scope is HIPAA configuration guidance, not general legal advice; it is useful for data-flow claims but must not be treated as a universal permission for regulated data. Confidence: HIGH for described data flow, MEDIUM for generalizing outside HIPAA context. Volatility: MEDIUM. — [HIPAA configuration guide for Codex](https://learn.chatgpt.com/docs/hipaa-configuration)

### Inferences

- 교육에서 안전한 구분은 “Business/Enterprise/Edu 기본값: model training에 사용하지 않음”과 “개인용 workspace 또는 개인 plan: training controls/opt-out 상태 확인 필요”를 분리하는 것이다. 이 inference는 official pages의 plan-specific data-use distinction에 근거한다.
- Codex 소스코드와 task data는 local/cloud 실행 표면과 인증 방식에 따라 흐름이 달라진다. Local은 작업 파일·명령이 사용자 환경에서 실행되더라도 prompts/files가 inference를 위해 OpenAI로 전송될 수 있고, Cloud는 OpenAI-managed environment에서 repository checkout과 task execution이 일어난다. 회사 코드 사용 허용 여부는 이 제품 사실로부터 자동 도출되지 않는다.
- “OpenAI가 기본적으로 business data를 training에 쓰지 않는다”는 말은 “조직 관리자가 app/connectors, retention, export, audit, sharing opt-in, policy를 어떻게 설정해도 무관하다”는 뜻이 아니다. Managed account 문서상 administrator controls와 organization agreement가 적용된다.

### Gaps

- 특정 회사 workspace가 Business인지 Enterprise인지, Codex seat/Cloud/Local/API sign-in 중 무엇을 쓰는지, organization owner가 어떤 opt-in 또는 admin setting을 적용했는지는 확인하지 않았다.
- Codex full-environment training controls의 정확한 UI 위치, default state, workspace-level enforceability는 이 조사에서 별도 공식 canonical page를 확보하지 못했다.
- 회사 소스코드, 고객 데이터, credentials, internal repository metadata가 허용되는지에 대한 회사 내부 정책은 확인하지 않았다.

## Retention, residency, deletion, local/cloud data flow는 어떻게 나뉘는가?

### Takeaway

Data residency는 저장 위치, inference residency는 GPU inference 위치, retention/deletion은 workspace plan과 policy에 따른 별도 문제다. Codex local/worktree/cloud도 실행 위치와 보관 책임이 다르며, Apps/MCP/Web/Search 같은 외부 통합은 data-residency boundary 밖으로 나갈 수 있다.

### Cited Findings

- Data residency and inference residency article은 ChatGPT data residency가 in-scope customer content의 storage at rest location을 정하고, inference residency가 eligible Enterprise/Edu customer의 supported region에서 GPU inference를 in-region으로 수행하게 한다고 설명한다. It explicitly says data residency does not include all user/system data, and inference residency does not confine all processing to region. Updated: 2026-09-19 around checked date. Confidence: HIGH. Volatility: HIGH because regions/features can change. — [Data residency and inference residency for ChatGPT](https://help.openai.com/en/articles/9903489-data-residency-for-chatgpt)
- 같은 residency article은 Apps & MCP, Web Search, external integrations를 통해 OpenAI infrastructure 밖에서 저장·처리되는 data가 selected region 밖에 있을 수 있다고 설명한다. It also states Codex Web is unsupported for data/inference residency while Codex app and CLI are supported. Scope: residency only, not training or permission. Confidence: HIGH. Volatility: HIGH. — [Data residency and inference residency for ChatGPT](https://help.openai.com/en/articles/9903489-data-residency-for-chatgpt)
- ChatGPT Business content storage article은 Business data residency가 gradual rollout이고 모든 customer에게 아직 available하지 않으며, region outside US를 선택해도 safety/abuse-monitoring data는 US에 저장되고 prompt/response copy가 limited time 동안 US에 저장될 수 있다고 설명한다. It says this Business article does not describe Enterprise/Edu exceptions. Updated: 2026-08-30 around checked date. Confidence: HIGH for Business scope. Volatility: HIGH. — [Where your ChatGPT Business content is stored](https://help.openai.com/en/articles/20001418-where-your-chatgpt-business-content-is-stored)
- Chat and file retention article says after a GPT, project, or file is deleted, OpenAI schedules associated data for permanent deletion within 30 days unless security/legal obligations require longer retention. It also says Enterprise transient files can expire after 48 hours unless another retention period applies, and backups may retain inactive Library files for up to 30 additional days unless longer retention is required. Scope: ChatGPT chat/file retention, feature-specific. Confidence: HIGH. Volatility: MEDIUM. — [Chat and file retention in ChatGPT](https://help.openai.com/en/articles/8983778-how-do-i-opt-out-of-my-data-being-used-to-train-future-models)
- Member removal article says Enterprise/Edu removed member content follows workspace retention policy; Business workspace chats/files/canvas are retained indefinitely and restored if member is re-added. It also distinguishes user removal from content deletion. Updated: 2026-07 around checked date. Confidence: HIGH. Volatility: MEDIUM. — [Data retention when a member is removed from a workspace](https://help.openai.com/en/articles/8266418-does-a-member-lose-access-to-chat-history-and-files-if-removed-from-a-workspace-and-will-the-chats-be-restored-if-the-member-is-re-added)
- Codex cloud environments article says a cloud task creates a container, checks out the selected branch or commit SHA, runs setup/maintenance scripts, applies internet settings, then agent loops through terminal commands, edits code, runs checks, and shows answer plus diff. It says secrets are decrypted only for task execution and are available only to setup scripts, then removed before agent phase. It also says caches may be shared across Business/Enterprise users who have access to the environment. Scope: Codex Cloud environment operation. Confidence: HIGH. Volatility: HIGH for product implementation details. — [Cloud environments](https://learn.chatgpt.com/docs/environments/cloud-environment)
- Codex environments article distinguishes Local, Worktree, and Cloud: Local works directly in current project directory; Worktree isolates changes in a Git worktree; Cloud runs remotely in a configured cloud environment. It says Local and Worktree chats run on the user’s computer. Scope: Codex environment mode. Confidence: HIGH. Volatility: MEDIUM-HIGH. — [Codex environments](https://learn.chatgpt.com/docs/environments/modes)
- Self-hosted sandboxes API guide says OpenAI runs the agent harness while the customer runs `codex exec-server` in the customer environment; the executor reads/writes files and runs shell commands at harness request over outbound WebSocket. It warns agents sharing an environment can access the same files, credentials, and resources. Scope: Agents API self-hosted sandbox, not all Codex surfaces. Confidence: HIGH. Volatility: MEDIUM-HIGH. — [Self-hosted sandboxes](https://developers.openai.com/api/docs/guides/agents-api/environments/self-hosted)

### Inferences

- 교육에서는 “local”을 “model inference가 local-only”로 설명하지 않는다. Local/Worktree는 files and commands run on user computer, but prompts/files may be sent to OpenAI for inference; Cloud is OpenAI-managed compute; self-hosted sandbox is customer compute connected to OpenAI agent harness.
- Residency claims must be scoped. “Data residency enabled” does not imply every app, MCP, web search, third-party service, Codex Web, log, metadata, CPU processing step, or abuse-monitoring copy stays in-region.
- Deletion and retention should be taught as workspace/feature/policy-specific, not as a single universal “30 days” or “indefinite” rule. Business, Enterprise/Edu, Library files, transient files, member removal, and Compliance API paths differ.

### Gaps

- The exact retention behavior for every Codex task artifact, local transcript, cloud container cache, Git diff, plugin app log, and external service record was not comprehensively documented in one official source.
- Whether a given organization has data residency, inference residency, Compliance API, or custom retention enabled is not knowable from public docs.
- The Trust Portal may contain additional security whitepapers such as Codex Security Whitepaper, but those require organization access and were not inspected here.

## Admin controls, Apps/Plugins/MCP, workspace analytics, and plan/role availability

### Takeaway

Business/Enterprise workspace behavior is controlled by admins, roles, app/plugin settings, provider permissions, and product availability. Apps/Plugins/MCP can expose business systems to ChatGPT/Codex, but OpenAI docs repeatedly separate plugin installation, app access, provider authorization, action permissions, sync/indexing, and workspace RBAC.

### Cited Findings

- Managed account data access article says organization administrators may access, export, audit, retain, delete, and opt in to share data tied to the managed account, including prompts, uploaded files, outputs, conversation history, workspace content, usage/activity metadata, and security/privacy settings where enabled and allowed by law. It also says administrators decide which services/features members can access. Updated: 2026-09-23 around checked date. Confidence: HIGH. Volatility: MEDIUM. — [Data access for your managed ChatGPT account](https://help.openai.com/en/articles/20001067-data-access-for-your-managed-chatgpt-account)
- ChatGPT Enterprise admin quickstart tells owners to confirm owners/admins, identity provider, groups, security/compliance/logging/retention/network controls, and which members should use Work and Codex before broad rollout. Scope: Enterprise setup guidance. Confidence: HIGH. Volatility: MEDIUM. — [ChatGPT Enterprise admin quickstart](https://help.openai.com/en/articles/20001264)
- Roles and workspace permissions article distinguishes ChatGPT workspace access/RBAC, local client runtime policy, Codex cloud eligibility, Platform API organization/project membership, and connected service permissions. It notes Owner, Admin, Member, Analytics Viewer roles and says Analytics Viewer can access workspace analytics. Scope: role model. Confidence: HIGH. Volatility: HIGH for feature availability. — [Roles and workspace permissions](https://learn.chatgpt.com/docs/enterprise/roles-and-workspace-permissions)
- Workspace settings article says owners/admins control workspace-wide settings such as permissions, seat types, spend controls, and access to ChatGPT and Codex features, and can manage members, feature access, GPT governance, apps, analytics, and identity controls. Scope: ChatGPT Enterprise. Confidence: HIGH. Volatility: HIGH. — [Managing workspace settings in ChatGPT Enterprise](https://help.openai.com/en/articles/8411955)
- Plugins in ChatGPT and Codex article says plugins can package Skills, connected apps, and app templates. Installing a plugin can start app connection/setup, but cannot bypass provider or workspace permissions. Availability depends on plan, workspace, role, region, and included capabilities; OpenAI Verified badge does not replace organization privacy/security/vendor review. Scope: Plugins in ChatGPT/Codex. Confidence: HIGH. Volatility: HIGH. — [Plugins in ChatGPT and Codex](https://help.openai.com/en/articles/20001256/)
- Admin controls for plugins/apps article says plugin installation and underlying app access are separate controls; Enterprise/Edu can use RBAC for plugin installation and app access; Business admins manage workspace-wide availability. It says action controls, permissions, provider approval, OAuth scopes, workspace restrictions, and safety protections are separate checks. It also states business workspace content, including information accessed through apps, is not used to train models by default. Updated: 2026-09 around checked date. Confidence: HIGH. Volatility: HIGH. — [Admin controls, security, and compliance for plugins and apps](https://help.openai.com/en/articles/11509118)
- Developer mode and MCP apps article says full MCP support including modify/write actions is rolling out in beta to ChatGPT Business, Enterprise, and Edu, and functionality/UI/permissions may change. Admins/owners can enable developer mode, publish MCP apps, configure actions/access, and see risk warnings for write/modify actions; organizations are responsible for vetting apps/connectors. Scope: ChatGPT developer mode/MCP apps. Confidence: HIGH. Volatility: HIGH. — [Developer mode and MCP apps in ChatGPT](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt)
- Plugin controls article says when ChatGPT uses an MCP server included with a plugin, it sends a request to the connected service and returns data/action results allowed by the authenticated user’s permissions in that service. It also states ChatGPT and Codex use the same public plugin directory on supported surfaces while admins decide which plugins are available. Scope: plugin controls, with UI labels app/MCP used interchangeably. Confidence: HIGH. Volatility: HIGH. — [Plugin controls](https://learn.chatgpt.com/docs/enterprise/apps-and-connectors)
- Administrator-managed apps with sync article says admin-managed sync does not grant users content they cannot view in the provider; workspace admins control connected sources and roles/groups, provider permissions determine accessible content, and selected source scope can further limit indexing. It also says ordinary app connections, actions, and indexed search may have different availability and permissions. Scope: sync/indexing only. Confidence: HIGH. Volatility: HIGH. — [Administrator-managed apps with sync](https://help.openai.com/en/articles/10847137-administrator-managed-apps-with-sync-in-chatgpt)
- Workspace Analytics article says raw logs, legal/security workflows, and compliance controls use Compliance API, while Workspace Analytics reports cleaned analytics data; counts can differ. It includes messages associated with app-tool routing and may include app- or connector-backed tool activity depending on workflow. Scope: Enterprise/Edu analytics. Confidence: HIGH. Volatility: MEDIUM-HIGH. — [Workspace analytics for ChatGPT Enterprise and Edu](https://help.openai.com/en/articles/10875114)
- Role-based access control article says admins can configure feature access via Workspace settings or Admin Console; Lockdown Mode can restrict network-enabled capabilities including live web search, deep research, agent mode, Canvas networking, and some app/MCP/connector behavior depending on settings. Scope: Business/Enterprise/Healthcare/Edu where RBAC supported. Confidence: HIGH. Volatility: HIGH. — [Managing feature access with RBAC](https://help.openai.com/en/articles/11750701-managing-feature-access-with-role-based-access-control-in-chatgpt)

### Inferences

- 교육에서 “연결하면 접근 가능”이라고 단순화하면 안 된다. 실제 접근은 workspace feature availability, plugin/app availability, user role, app action controls, provider OAuth/provider-side permissions, sync/indexing setup, and approval settings의 교집합이다.
- Apps/Plugins/MCP data boundary is shared responsibility. OpenAI workspace defaults may protect model training use, but information sent to third-party services follows provider terms and organization configuration; OpenAI Verified status or plugin installation is not company approval.
- Workspace Analytics is not a full compliance log. For audit/legal/security workflows, docs point to Compliance API; analytics may be cleaned and can differ from raw logs. Training materials should not promise admins can see or export every event unless the specific Compliance API coverage is confirmed.
- Plan/account/role availability is volatile. Business vs Enterprise vs Edu, local vs cloud, API-authenticated vs ChatGPT-authenticated Codex, and regional/residency settings must be checked in the actual target training workspace before Demo.

### Gaps

- The target company’s workspace plan, enabled seats, Codex cloud availability, plugin policy, RBAC roles, Lockdown Mode, Compliance API coverage, retention, residency, and app allowlist are unknown.
- Public docs do not establish whether the company permits internal source code, customer data, tickets, docs, Slack/Linear content, GitHub/GitLab repositories, secrets, or regulated data in ChatGPT/Codex.
- Some policy pages and Help Center articles are updated frequently and may have changed UI labels or controls by Demo time. All product-specific screenshots and claims need a final recheck in the target account.
