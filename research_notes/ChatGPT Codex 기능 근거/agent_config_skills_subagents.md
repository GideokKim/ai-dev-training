Research checked: 2026-09-25. Sources are OpenAI Codex / ChatGPT documentation,
OpenAI developer documentation, and the official `openai/codex` repository.

## AGENTS.md

### Takeaway

`AGENTS.md` is an officially documented Codex instruction mechanism. Codex
loads global and project guidance using a documented directory walk and
concatenation order. “Context Router” is a useful training label for a project
pattern that points an agent to task-relevant documents; it is not the name of
an AGENTS.md product feature in the official documentation.

### Cited Findings

- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** Codex clients covered by the Codex agent-configuration guide. Codex officially reads `AGENTS.md` instructions before work and builds an instruction chain at startup / session start. [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** Global Codex configuration. Codex home defaults to `~/.codex` and can be changed with `CODEX_HOME`. At global scope it reads `AGENTS.override.md` when present, otherwise `AGENTS.md`; it uses only the first non-empty global file. [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** Project instructions. Starting at the project root (typically the Git root), Codex walks down to the current working directory. In each directory it checks `AGENTS.override.md`, then `AGENTS.md`, then configured `project_doc_fallback_filenames`, and includes at most one file per directory. Without a discovered project root, it checks only the current directory. [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** The loaded project files are concatenated root-to-leaf with blank lines; the docs say more-specific, later files override earlier guidance. Empty files are skipped. Combined instruction loading stops at `project_doc_max_bytes`, documented as 32 KiB by default; the cap and fallback filenames are configurable. This is an instruction-prompt merge, not a documented deterministic key/value override engine. [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- **FACT | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: MEDIUM | Scope:** Officially documented instruction precedence covers global Codex-home guidance followed by project-root-to-working-directory guidance. The page does not specify a complete authority hierarchy among model/system/developer instructions, the current user prompt, and AGENTS.md, nor does it define deterministic conflict-resolution semantics beyond the discovery and concatenation order. [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- **HEURISTIC | Confidence: HIGH | Checked: 2026-09-25 | Source date: 2026-09-11 | Volatility: MEDIUM | Scope:** OpenAI’s GPT-6 Astra guidance recommends keeping AGENTS.md current and avoiding unconditional requests to read many documents before every edit. It illustrates conditional pointers such as consulting architecture guidance for service boundaries and database guidance for schema changes. It warns that broad always-read instructions spend context and slow tasks. [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)
- **FACT / PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: MEDIUM | Scope:** Official examples support repository-wide norms in the root AGENTS.md and specialized rules in nested files; code-review rules should be placed closest to the code they govern. The guide recommends concise rules that state behavior to flag and a safe path/exception, and says formatting/lint checks are better left to CI. [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- **TEACHING MODEL / PROJECT CONVENTION | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown for AGENTS.md docs; 2026-09-11 for the blog | Volatility: LOW as a label, HIGH as product behavior | Scope:** “Context Router” is not used as the product name or official AGENTS.md concept in the cited Codex guide. Describing an AGENTS.md as a short map that directs the agent to task-relevant project documents is a training/project pattern inferred from the official hierarchical instruction mechanism and OpenAI’s conditional-document-pointer guidance. The router label should be explicitly attributed to this course, not to Codex. [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md); [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)

### Inferences

- An AGENTS.md can be taught as an “instruction layer plus links to relevant project knowledge”: the instruction-file discovery/precedence is product behavior, while the “router” name and deliberate routing architecture are this course’s **TEACHING MODEL / PROJECT CONVENTION**. This inference combines the documented directory hierarchy with OpenAI’s 2026-09-11 recommendation to make document references conditional on the task. [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md); [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)
- For a demo, show root guidance and one nested override, then ask Codex which instruction sources it loaded from the root and nested directory. This is an **INDUSTRY PRACTICE / HEURISTIC** for making precedence observable, based on the official guide’s own verification examples; it does not prove that every model follows every instruction. [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

### Gaps

- The official page does not fully specify precedence against system/developer instructions or the user’s live prompt. Do not state that AGENTS.md can override higher-level instructions.
- Concatenation order is documented, but exact model behavior when two instructions conflict is not guaranteed by the page.
- The current guide did not display a publication/update date. Runtime details, byte limits, and client coverage should be rechecked before a future product-specific demo.

## Skills

### Takeaway

Skills are an official reusable-workflow format in Codex and ChatGPT. Codex skills use a `SKILL.md` manifest and can be discovered from repository, user, admin, and system locations. Both explicit invocation and description-based implicit selection are documented. Progressive disclosure is directly supported: the initial context has metadata and the full instructions load when Codex selects a skill.

### Cited Findings

- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** The official term is “Skills” / “agent skills.” OpenAI describes them as task-specific instructions, resources, and optional scripts for reusable workflows; the same guide lists standalone Skills in the ChatGPT desktop app, Codex CLI, and IDE extension. Plugin-bundled Skills are also available across ChatGPT Chat and Work surfaces and Codex. [Build skills](https://learn.chatgpt.com/docs/build-skills)
- **FACT / PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: MEDIUM | Scope:** A Skill is a directory with a required `SKILL.md`; its YAML front matter must include `name` and `description`. Codex’s documented optional files/folders include `scripts/`, `references/`, `assets/`, and `agents/openai.yaml` (UI metadata, policy, and dependencies). [Build skills](https://learn.chatgpt.com/docs/build-skills)
- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** Codex scans `.agents/skills` in each directory from the current working directory up to the repository root. Additional documented scopes are user `$HOME/.agents/skills`, admin `/etc/codex/skills`, and skills bundled with Codex by OpenAI. Codex follows symlinked skill folders. Two Skills with the same `name` do not merge; both may appear in selectors. [Build skills](https://learn.chatgpt.com/docs/build-skills)
- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** Codex supports explicit invocation (`/skills` to inspect and `$skill-name` to mention in CLI/IDE) and implicit invocation when a task matches the description. `agents/openai.yaml` can set `policy.allow_implicit_invocation: false`; the documented default is `true`, while explicit invocation remains available. ChatGPT’s explicit selection syntax is `@`. [Build skills](https://learn.chatgpt.com/docs/build-skills)
- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** Skill loading uses progressive disclosure. The initial Codex Skill list contains each Skill’s name, description, and path, capped at 2% of context or 8,000 characters when context size is unknown; if many Skills are present, descriptions can be shortened and some Skills omitted with a warning. When Codex decides to use a Skill, it reads that Skill’s full `SKILL.md`. [Build skills](https://learn.chatgpt.com/docs/build-skills)
- **FACT / PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: MEDIUM | Scope:** Official docs say Skills package instructions, resources, and optional scripts for workflows, and recommend focused Skills with explicit inputs/outputs. References and assets can provide documentation/templates; scripts are executable code. The docs do not say that every referenced resource is automatically loaded with `SKILL.md`; treat resource loading as conditional and do not claim that all files enter context at once. [Build skills](https://learn.chatgpt.com/docs/build-skills)
- **FACT / TEACHING MODEL | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: LOW for the distinction | Scope:** “Reusable workflow” is an accurate official description of Skills. Turning repeated workflow friction into a Skill is a sensible **HEURISTIC / TEACHING MODEL**, not a required product condition: official docs describe reusable workflows and recommend one focused job per Skill but do not require a minimum number of repetitions. [Build skills](https://learn.chatgpt.com/docs/build-skills)
- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** Codex detects local Skill changes automatically; the docs advise restarting Codex if an update does not appear. [Build skills](https://learn.chatgpt.com/docs/build-skills)

### Inferences

- **Demo feasibility: HEURISTIC | Confidence: MEDIUM | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH:** A short deterministic demo can create a minimal repository Skill at `.agents/skills/review-checklist/SKILL.md`, include only `name`, `description`, and concise review instructions, then explicitly invoke `$review-checklist` in Codex. A separate optional pass can show implicit selection from a narrowly worded description. Explicit invocation is the more reproducible teaching path because implicit selection is model-selected. This is a proposed demo based on documented discovery and invocation; it was not executed as part of this research. [Build skills](https://learn.chatgpt.com/docs/build-skills)
- A folder named `skills/` at the repository root or `.codex/skills/` should not be presented as Codex’s documented local repository discovery location; the current Codex docs specify `.agents/skills`. Plugin packaging uses a separate `skills/<name>/SKILL.md` path. **PRODUCT BEHAVIOR / FACT**, scoped respectively to local discovery vs plugin package structure. [Build skills](https://learn.chatgpt.com/docs/build-skills); [Build plugins](https://developers.openai.com/plugins/build/plugins)

### Gaps

- The official page does not promise that implicit invocation will trigger for a particular prompt. Use explicit `$skill-name` for a reliable demonstration and treat auto-selection as a model behavior to observe, not a guaranteed result.
- The page documents references and resources but does not specify exact rules for when every supplementary file is opened or how those files consume context. Avoid categorical claims about resource auto-loading.
- UI locations and eligible product surfaces can change. The page did not expose a source publication/update date; recheck availability and invocation UI before recording a demo.

## Subagents

### Takeaway

“Subagent” and “subagent workflow” are official Codex terms. Codex can delegate bounded independent work in parallel and return subagent summaries to the main thread. Role-specific instructions are configurable. Context separation exists as an explicit concept in official API/runtime sources, but exact context and filesystem isolation differ by product surface; Codex does not document automatic per-subagent worktree isolation. Parallel writing adds coordination and conflict risk.

### Cited Findings

- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** OpenAI’s Codex documentation names “Subagents” and “subagent workflows.” Current local Codex releases enable them by default in the ChatGPT desktop app, CLI, and IDE extension; ChatGPT Work availability is for eligible accounts. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** Codex can delegate when the user asks directly or applicable `AGENTS.md` / Skill instructions request it. The product guide’s supported pattern is independent subtasks running in parallel, followed by the main thread collecting results into its final response. ChatGPT Work generally expects an explicit request, with proactive delegation described for eligible Ultra/model combinations. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- **FACT / PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: MEDIUM | Scope:** Codex calls the delegated unit a “Subagent” and its work conversation an “agent thread.” Codex handles spawning, follow-up routing, waiting for results, and closing threads; the main thread receives a consolidated response/summary. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** Local Codex provides built-in `default`, `worker`, and `explorer` agents. Custom agents can be defined as separate TOML files under `~/.codex/agents/` (personal) or `.codex/agents/` (project). Each file requires `name`, `description`, and `developer_instructions`; supported settings can include model, reasoning effort, sandbox, MCP servers, and Skill configuration. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** Codex’s subagent guide says child agents run in their own agent threads and reduce the amount of noisy intermediate work in the main context. A separate OpenAI Agents API guide explicitly says each subagent has its own context; that statement is **Agents API behavior** and should not automatically be generalized to every Codex App/CLI configuration. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents); [Multi-agent (Agents API)](https://developers.openai.com/api/docs/guides/agents-api/multi-agent)
- **FACT / PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: current `main` page did not show a commit date | Volatility: HIGH | Scope:** The official `openai/codex` collaboration-tool specification exposes `fork_turns` values `none`, `all`, or a positive integer, to control how much surrounding conversation context is forked into a spawned subagent. This confirms selectable conversation-context inheritance for that collaboration-tool interface, not a universal default for all Codex surfaces. [openai/codex multi-agent tool specification](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/multi_agents_spec.rs#L3109-L3148)
- **PRODUCT BEHAVIOR / HEURISTIC | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** OpenAI recommends read-heavy parallel work such as exploration, tests, triage, and summarization as a starting point, and cautions that parallel write-heavy work can create conflicts and coordination overhead. It also says each subagent performs its own model/tool work, so parallel work consumes more tokens than a comparable single-agent run. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- **PRODUCT BEHAVIOR | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH | Scope:** Codex worktrees are documented as a way to run multiple independent **chats** in one Git project using separate checkouts. Worktree documentation does not say that each spawned subagent automatically receives its own worktree. Subagent docs explicitly caution about concurrent file-edit conflicts. Do not conflate chat/worktree isolation with subagent filesystem isolation. [Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees); [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- **HEURISTIC | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: LOW as a design recommendation | Scope:** For delegation, OpenAI advises defining a clear question, splitting independent work, stating whether to wait for all agents, and specifying the expected returned summary. This is guidance, not an execution guarantee. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)

### Inferences

- **Demo feasibility: HEURISTIC | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: HIGH:** A Codex demo can issue a direct prompt such as “Use three subagents in parallel: inspect architecture, assess performance risks, and identify test gaps. Keep the tasks read-only, wait for all three, and return separate evidence-backed summaries.” This matches the documented direct-trigger and parallel-result workflow. “Architecture,” “Performance,” and “Test” are task-defined roles; they are not the built-in Codex agent names. For stable repeated behavior, custom agents can encode role-specific `developer_instructions`. This proposal was not executed in the research subtask. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- **PROJECT CONVENTION / HEURISTIC | Confidence: HIGH | Checked: 2026-09-25 | Source date: not shown | Volatility: LOW:** Keep subagent assignments bounded and non-overlapping; favor read-only analysis during a live demo; ask the main agent to reconcile findings and state disagreements. This follows OpenAI’s coordination-cost and write-conflict cautions, but is this course’s recommended use pattern rather than a product requirement. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)

### Gaps

- The Codex App/CLI/IDE guide does not fully specify what conversation turns, project instructions, or Skill state are inherited in each subagent surface. The Agents API says subagents have their own context; the official Codex collaboration tool exposes context-fork controls. Keep those claims scoped to those interfaces.
- The current Subagents guide does not state that spawned agents share one working tree, nor does it promise a separate worktree per child. It warns of write conflicts, so filesystem isolation must remain **unconfirmed** unless verified for the precise client/version used in the demo.
- The worktree guide covers independent chats and separate Git checkouts, not automatic worktree provisioning for subagents. Do not imply that using a subagent automatically isolates file changes.
- Product availability and UI controls may differ by account, selected model, client, and release. Verify the exact demonstration environment before claiming that a particular class environment can run it.
