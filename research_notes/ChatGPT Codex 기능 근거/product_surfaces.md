# ChatGPT & Codex 제품 표면 조사 노트

조사 기준일: **2026-09-25**. 범위는 개발자가 사용하는 ChatGPT와 Codex 제품 표면, 실행 위치, 저장소 접근, 코드 수정·검증 및 리뷰 흐름이다. 아래 자료는 OpenAI의 공식 제품 페이지, 공식 문서, 공식 도움말만 사용했다. OpenAI 문서 페이지는 현재 문서로 확인했으며 게시·수정 일자를 노출하지 않는 경우에는 해당 사실을 명시했다. 가용성·플랜·관리자 통제는 조직별로 달라질 수 있으므로 개인/조직의 실제 계정에서 재확인이 필요하다.

## ChatGPT 개발자 사용과 Codex의 관계

### Takeaway

ChatGPT는 코드 설명·질문·자료 검토를 위한 대화형 표면이며, 연결한 GitHub 앱은 권한이 부여된 저장소를 읽고 검색할 수 있지만 그 연결만으로 저장소 파일을 수정하거나 push하지 않는다. Codex는 저장소 환경에서 파일을 조사·편집하고 명령 및 검증 단계를 수행하도록 설계된 코딩 에이전트다. OpenAI는 Codex를 ChatGPT, IDE, 터미널에서 같은 계정과 이어지는 하나의 코딩 에이전트 경험으로 제시한다. [ChatGPT GitHub 연결 도움말](https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt), [Codex 제품 페이지](https://openai.com/codex/)

- 도움말은 ChatGPT의 GitHub 앱이 **저장소 읽기 전용**이며, 코드 생성·편집·GitHub push는 Codex를 사용하라고 명시한다. 따라서 “ChatGPT GitHub 연결 = 로컬 working tree 편집 권한”이라고 설명하면 부정확하다. **Checked:** 2026-09-25. **Source date:** 위 도움말 “Updated: 10 hours ago”. **Evidence:** 공식 도움말, 1차 근거. **Confidence:** 높음. **Volatility:** 높음. **Unknowns:** Codex에서 push/PR을 수행하기 위한 구체적 저장소·권한 조건은 사용 표면(Cloud/CLI), 인증 방식과 조직 정책에 따라 다르므로 각 흐름 문서를 확인해야 함. - **ChatGPT desktop app — ChatGPT와 Codex가 선택 가능한 모드.** 사용자는 앱에서 chat, project 또는 folder를 열 수 있고, ChatGPT는 선택 위치의 파일과 context를 사용할 수 있다. 첫 작업을 시작할 때 ChatGPT 또는 Codex를 선택하며, ChatGPT 안에서는 Chat 또는 Work를, Codex에서는 새 Codex chat을 시작한다. 이는 두 제품 흐름이 하나의 앱에서 보일 수 있음을 설명하지만 ChatGPT 모드가 Codex와 동일한 로컬 명령 실행·저장소 편집 기능을 제공한다고 뜻하지 않는다. **Checked:** 2026-09-25. **Source date:** 현재 제품 문서가 게시/수정 일자를 노출하지 않음. **Evidence:** 공식 ChatGPT 제품 문서, 1차 근거. **Confidence:** 높음. **Volatility:** 중간~높음(앱 UI, 모드, OS 지원 변경 가능). **Unknowns:** 폴더를 여는 ChatGPT 모드에서 어떤 파일 작업을 허용하는지는 각 OS·권한·모드의 현재 설정에 좌우됨. - **Codex의 제품 관계.** OpenAI 제품 페이지는 Codex를 ChatGPT, IDE, terminal에서 쓸 수 있고 ChatGPT 계정으로 연결되는 “same agent”라고 표현한다. Codex 제품 페이지는 parallel work, cloud environments, worktrees, code review 등을 agentic coding 기능으로 소개한다. 이는 사용 표면이 다르더라도 코딩 에이전트 제품군이라는 공식 정체성을 뒷받침한다. **Checked:** 2026-09-25. **Source date:** 제품 페이지 게시/수정 일자 미표시. **Evidence:** 공식 제품 설명(일부 마케팅 성격), 1차 근거. **Confidence:** 표면 간 연결은 높음; 구체적인 기능 일치 범위는 중간. **Volatility:** 높음. **Unknowns:** 모든 표면에서 동일한 기능·모델·권한·가용성이 제공되는지는 보장하지 않음. - **ChatGPT Work의 코드 검토 경계.** 공식 Code Review 문서는 ChatGPT Work에서 검토할 코드를 업로드하거나 설치된 source plugin으로 접근 가능하게 한 뒤 PR/branch/commit/files/criteria를 prompt에 명시하는 방식을 제시한다. 반면 `/review`는 Codex의 App, CLI, IDE review workflow이며 Git repository에 있는 작업을 리뷰한다. 따라서 교육에서는 “ChatGPT에 코드를 제공해 분석”과 “Codex가 연결된 Git diff를 리뷰”를 별도 수행 맥락으로 설명할 수 있다. **Checked:** 2026-09-25. **Source date:** 문서 게시/수정 일자 미표시. **Evidence:** 공식 문서, 1차 근거. **Confidence:** 높음. **Volatility:** 중간~높음. **Unknowns:** 회사의 설치된 source plugin 목록, ChatGPT Work 기능 노출 여부, 각 플랜의 접근 조건. ### Inferences

- **교육 패턴(기획 적용이지 제품 요구사항은 아님):** 작은 코드 발췌·개념 질문·작업 요구 정리에서는 ChatGPT 대화로 시작하고, 실제 저장소 맥락을 탐색하거나 수정·명령·검증이 필요하면 Codex에 저장소 접근을 제공하는 흐름이 제품 경계와 잘 맞는다. 이는 ChatGPT GitHub 연결이 read-only이고 Codex가 repository 변경 작업을 담당한다는 제품 설명에서 도출한 교육 설계 제안이며 OpenAI가 규정한 필수 순서가 아니다. [ChatGPT GitHub 연결](https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt), [Codex 제품 페이지](https://openai.com/codex/)
- GitHub 연동도 표면/권한별로 차이가 있으므로 “AI가 GitHub에 연결된다”만으로는 불충분하다. 어떤 표면인지, 연결된 계정이 어떤 저장소에 접근 가능한지, 그 동작이 read-only인지 작업 가능한 에이전트인지를 함께 가르치는 편이 정확하다.

### Gaps

- ChatGPT GitHub 기능의 지원 플랜·Workspace 관리자 통제·표면별 롤아웃은 동적이다. 사내 교육 전에 대상 Workspace에서 표준 Chat, Work, Codex Cloud 각각의 사용 가능 여부와 GitHub 앱 정책을 확인해야 한다.
- 현재 제품 페이지에는 Codex의 정확한 현행 플랜별 사용량·한도 표가 없다. 2026-02-02 Codex 앱 출시글은 당시 Plus/Pro/Business/Enterprise/Edu 사용 가능과 Free/Go 한시 제공을 안내했지만 한시 제공은 현재 상태의 근거로 사용할 수 없다. 출시글 게시일은 2026-02-02, Windows 앱 업데이트는 2026-03-04다. 현재 가용성은 출시글이 아니라 대상 계정의 플랜 및 관리자 설정에서 재확인해야 한다. [출시글](https://openai.com/index/introducing-the-codex-app/)

## Codex 표면, 실행 위치와 개발 작업 능력

### Takeaway

현재 Codex 표면은 terminal CLI, IDE 통합, ChatGPT desktop app의 Codex 모드, Codex cloud로 나뉜다. 가장 중요한 차이는 UI가 아니라 에이전트가 어떤 파일·저장소·명령 환경에서 실행되는가다. Local CLI/IDE는 개발자의 로컬 프로젝트와 설치된 도구를, Cloud는 선택된 branch/commit의 저장소를 기반으로 별도 container와 setup을 사용한다. [CLI 문서](https://developers.openai.com/codex/cli), [IDE 문서](https://developers.openai.com/codex/ide), [Cloud environments 문서](https://learn.chatgpt.com/docs/environments/cloud-environment)

### Cited Findings

- **Codex CLI — local repository workflow.** CLI는 프로젝트 디렉터리에서 실행하여 로컬 파일을 조사·편집하고, 컴퓨터에 이미 설치된 도구를 실행한다. 지원되는 local loop에는 코드베이스 설명, 변경 계획, 파일 편집, local development tools 실행, 진행 중 명령·diff 확인, follow-up이 포함된다. macOS/Linux 설치 흐름이 문서화되어 있고 Windows 설치도 안내한다. prerequisite는 CLI 설치, sign-in, 프로젝트 디렉터리에서의 실행이다. `codex exec`는 반복 가능한 workflow/CI에 사용할 수 있다. **Checked:** 2026-09-25. **Source date:** 제품 문서 게시/수정 일자 미표시. 같은 날짜의 공식 changelog가 최신 CLI release를 `0.157.0`으로 표시. **Evidence:** 공식 CLI 문서 및 릴리스 로그, 1차 근거. **Confidence:** 높음. **Volatility:** 높음(명령 및 버전 변경 잦음). **Unknowns:** CLI 실행 권한·사용 모델은 인증, 설정, OS, 조직 정책에 좌우됨. [CLI 문서](https://developers.openai.com/codex/cli), [2026-09-25 changelog](https://developers.openai.com/codex/changelog)
- **Codex IDE integrations — editor context and local edits.** IDE 통합은 열려 있는 파일·선택한 코드·최근 chat을 context로 포함하고, 에디터 옆에서 수정 요약과 diff를 확인하고 후속 지시를 보낼 수 있다. Codex extension은 VS Code 및 호환 편집기(Codex 문서에 Cursor, Windsurf 포함)에서 제공되며 Xcode와 JetBrains IDE에는 자체 integration이 안내되어 있다. 빠른 편집은 local에서 하고 더 긴 작업은 Codex web으로 넘길 수 있다. prerequisite는 해당 IDE/integration 설치 또는 활성화, sign-in, 프로젝트 열기다. **Checked:** 2026-09-25. **Source date:** 제품 문서 게시/수정 일자 미표시. **Evidence:** 공식 IDE 문서, 1차 근거. **Confidence:** 높음. **Volatility:** 중간~높음(지원 IDE·extension 기능 변경). **Unknowns:** IDE별 버전 호환성, enterprise 관리 배포 여부, 사용 가능한 모델은 별도 확인 필요. [출처](https://developers.openai.com/codex/ide)
- **Codex desktop app — parallel project workspace.** 현재 ChatGPT desktop 문서는 앱에서 ChatGPT 또는 Codex를 선택하는 경험을 보여주며, Codex 쪽은 desktop project context로 long-running tasks 및 worktrees를 쓸 수 있다. 현재 문서의 ChatGPT desktop 앱 quickstart는 macOS, Windows, Linux 설치를 안내한다. 단, Codex app의 플랫폼 rollout과 계정 entitlement는 제품 발표/계정마다 달라질 수 있다. **Checked:** 2026-09-25. **Source date:** 문서 게시/수정 일자 미표시. 2026-02-02 OpenAI announcement는 당시 macOS 출시 및 parallel agent threads를 설명하고 2026-03-04 Windows availability update를 기록. **Evidence:** 현행 공식 문서 + 날짜가 표시된 제품 발표. **Confidence:** 앱에서 ChatGPT/Codex 선택은 높음; 개별 OS/account에서 Codex feature entitlement는 중간. **Volatility:** 높음. [현행 desktop 문서](https://developers.openai.com/codex/app), [제품 발표 및 플랫폼 업데이트](https://openai.com/index/introducing-the-codex-app/)

- **Codex cloud — isolated repo checkout and iterative code work.** Cloud task 제출 시 Codex가 선택 branch 또는 commit SHA에서 repository를 container에 checkout하고 setup script/선택적 maintenance script를 실행한다. 그 뒤 agent가 terminal command loop에서 코드를 편집하고 check를 실행해 결과를 검증하려고 시도한다. `AGENTS.md`가 있으면 프로젝트의 lint/test 명령을 찾는 데 활용한다. 완료 시 답변과 변경 파일 diff를 보여주며 PR 생성 또는 추가 요청으로 이어갈 수 있다. 기본 universal image에는 흔한 언어·패키지·도구가 포함되고, dependency 설치를 위한 자동 또는 custom setup이 가능하다. 필요한 사전조건은 Cloud 환경을 설정하고 Codex에 해당 repository access를 제공하는 것, 실행에 필요한 setup/dependencies를 준비하는 것이다. **Checked:** 2026-09-25. **Source date:** 공식 환경 문서 게시/수정 일자 미표시. **Evidence:** 공식 Cloud 환경 문서, 1차 근거. **Confidence:** 높음. **Volatility:** 높음(이미지, setup lifecycle, Git provider 지원, rollout 변경 가능). **Unknowns:** 사내 GitHub Enterprise/network restrictions, 해당 저장소의 private dependency 설치 여부, 관리자 policy. ### Inferences

- **실행 위치는 Context의 일부(교육용 해석).** 동일한 요청이라도 Local/IDE, local worktree, Cloud container 중 어디에서 처리되는지에 따라 접근 가능한 저장소 상태, 설치 도구, 네트워크, 데이터가 다르다. 따라서 “어떤 모델인가?”만 아니라 “어디에서 무엇을 읽고 실행하는가?”가 agent 결과와 보안 검토에 영향을 준다. 근거는 local repo, cloud checkout, cloud network 정책의 서로 다른 공식 설명이다. [Local environment](https://learn.chatgpt.com/docs/environments/local-environment), [Cloud environments](https://learn.chatgpt.com/docs/environments/cloud-environment), [Cloud internet access](https://learn.chatgpt.com/docs/cloud/internet-access)
- Codex Cloud가 check를 실행하고 “validate하려고 한다”는 것은 제품이 검증 루프를 수행할 수 있다는 사실이지, 그 테스트가 충분하다거나 결과가 항상 맞다는 보장은 아니다. 교육에서는 실행된 command, 결과, 실패, 변경 diff를 직접 읽어야 한다. [Cloud environments](https://learn.chatgpt.com/docs/environments/cloud-environment), [Code review](https://learn.chatgpt.com/docs/third-party/github)

### Gaps

- Desktop app 내 Codex 기능의 OS별 지원 조건, 플랜/usage limit, organization-level disablement는 공식 제품 소개와 현행 문서만으로 모든 회사 계정에 대해 단정할 수 없다. 수강생이 사용할 계정·OS에서 최종 확인해야 한다.
- Codex Cloud의 GitHub Enterprise 및 사내 자체 호스팅 저장소 접근은 조직 연결/네트워크 정책에 따라 다르다. 각 회사 환경의 정확한 지원 범위를 별도 확인해야 한다.
- 문서가 설명하는 “common tools”, automatic setup, universal image는 각 언어·프로젝트의 모든 toolchain이나 test dependency가 미리 들어 있다는 뜻이 아니다. 실제 repository에서 설치/테스트 가능 여부는 Demo 환경으로 확인할 항목이다.

## Parallel work, worktrees, review, safety와 교육 이야기

### Takeaway

Codex는 Git repository를 전제로 worktree로 격리된 작업을 병렬 처리하고, 코드 diff를 local/App/IDE 또는 GitHub PR review에서 검토하도록 지원한다. `/review`는 선택한 Git diff에 대한 별도 review이며 working tree를 변경하지 않는다고 문서화되어 있다. 제품이 코드 편집과 test 명령 실행을 할 수 있어도 사람의 검토와 실제 검증 책임을 대체한다는 근거는 없다. [Worktrees 문서](https://learn.chatgpt.com/docs/environments/git-worktrees), [Code review 문서](https://learn.chatgpt.com/docs/code-review), [GitHub PR review 문서](https://learn.chatgpt.com/docs/third-party/github)

### Inferences

- **지속 가능한 Engineering insight:** 제품 UI와 선택 모델은 바뀌어도, agent가 실제 변경을 만들려면 context → 가능한 tool/action → 실행 환경 → 관찰 가능한 결과 → 수정/재검증 루프가 필요하다. OpenAI의 2026-01-23 loop 설명이 제품 기반을 제공하지만 이를 장기간 유효한 교육 원칙으로 일반화하는 부분은 기술적 추론이다. [Codex agent loop 설명](https://openai.com/index/unrolling-the-codex-agent-loop/)
- **용어 경계—Harness와 Loop:** OpenAI의 2026-01-23 기술 글은 Codex harness를 제품의 핵심 agent-loop/execution logic으로 설명한다. 이는 이 교육의 `Harness Engineering` 정의와 자동으로 같은 뜻이 아니다. 또한 OpenAI 글의 per-task user/model/tool 반복은 제품 실행 loop의 근거로 쓸 수 있지만, 이 교육의 `Loop Engineering`은 반복 Failure/Friction을 관찰해 Harness나 작업 시스템을 개선하는 별도 개념이며 단순 반복 실행으로 축소하지 않는다. 이 구분은 OpenAI 제품 용어와 프로젝트의 승인된 정의를 함께 대조한 것이다. [OpenAI Codex agent loop 글](https://openai.com/index/unrolling-the-codex-agent-loop/), [MASTER_PLAN.md](../../plan/MASTER_PLAN.md), [INVARIANTS.md](../../plan/INVARIANTS.md)
- **이 프로젝트의 교육 패턴:** MASTER_PLAN이 정한 `Chatbot → Prompt → Context → Harness → Loop`와 problem-driven evolution은 OpenAI 문서가 요구하는 단계 구분이 아니다. 제품 근거상 ChatGPT GitHub read-only와 Codex의 repository execution은 경계 사례를 제공하며, 교육 Story에서 “복사해 붙인 코드만 가진 질문”에서 “저장소 context·실행·검증이 갖춰진 Codex 작업”으로 확장하는 설명에 사용할 수 있다. 이 문장 전체의 순서와 서사는 제품 사실이 아니라 프로젝트가 승인한 교육 설계다. [ChatGPT GitHub 연결](https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt), [Codex Cloud 환경](https://learn.chatgpt.com/docs/environments/cloud-environment), [Codex agent loop 설명](https://openai.com/index/unrolling-the-codex-agent-loop/)
- “Codex가 tests를 실행했다”는 것은 특정 실행 기록의 사실일 수 있으나 “테스트가 통과해서 변경이 맞다” 또는 “제품이 자동으로 옳음을 보장한다”는 결론은 아니다. 결과의 명령·출력, 실제 변경 diff, 검토 범위를 대조해야 한다. [Cloud environments](https://learn.chatgpt.com/docs/environments/cloud-environment), [GitHub PR review](https://learn.chatgpt.com/docs/third-party/github)

### Gaps

- `worktree`, GitHub PR review, Auto-review 등 일부 기능은 특정 client/plan/account 설정이 필요할 수 있다. 현 문서 페이지에 게시일·릴리스 상태가 없는 기능은 교육일에 다시 열어 changelog와 대상 계정에서 확인할 것.
- 제품/문서에는 local sandbox의 OS별 구현과 조직별 policy 차이가 존재한다. 교육 Demo에서 어떤 OS·mode·approval policy를 사용할지는 Demo 환경을 정한 뒤 따로 검증해야 한다.
- 조사한 제품 자료는 조직 전체 AI 역량 균질화, 직접 실습 없음, 6시간 교육의 설계 요건을 정하지 않는다. 이는 이 프로젝트 `MASTER_PLAN`/`INVARIANTS`의 범위이며 제품 feature 근거와 혼합하지 않는다.
