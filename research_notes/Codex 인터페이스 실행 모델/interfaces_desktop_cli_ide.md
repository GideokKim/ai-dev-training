### 22. ChatGPT desktop app — Codex view

- **무엇인가:** 현재 공식 표기는 **ChatGPT desktop app**의 **Codex** view다. macOS·Windows에서 ChatGPT Chat/Work와 Codex를 한 앱 안에 담지만, Codex는 개발 작업용 별도 경험이며 Codex history도 ChatGPT history와 분리된다. 기존 Codex 앱 사용자는 업데이트 후 새 desktop app으로 이동한다. [Migration 안내](https://help.openai.com/en/articles/20001276-moving-to-the-new-chatgpt-desktop-app) · [Work and Codex FAQ](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)
- **OS:** 새 앱은 macOS와 Windows에서 제공된다. macOS 공식 요구사항은 macOS 14 이상 및 Apple Silicon M1 이상 또는 Intel Mac이다. Linux 데스크톱 앱은 Ubuntu 24.04/26.04, Debian 13, Fedora 43/44, 최신 Arch의 x64/ARM64 지원 preview로 표시되어 있고, 그 밖의 배포판은 공식 지원 범위 밖이다. Linux preview에는 macOS/Windows와 기능 차이(예: Computer Use 미지원)가 있다. [macOS requirements](https://help.openai.com/en/articles/9275200-using-the-chatgpt-macos-app) · [Linux preview matrix](https://learn.chatgpt.com/docs/linux/linux-app)
- **저장소와 환경:** local project/folder를 열어 Codex가 파일과 개발 도구를 사용한다. Windows에서는 PowerShell을 사용하는 Windows-native agent 및 native sandbox를 선택하거나 WSL2 agent로 전환할 수 있다. 통합 터미널 shell은 별도로 PowerShell, Command Prompt, Git Bash, WSL 중에서 선택 가능하다. [Windows desktop app](https://learn.chatgpt.com/docs/windows/windows-app) · [Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)
- **동시 작업과 격리:** 한 프로젝트에서 여러 chat을 작업별로 열 수 있고, Git worktree를 선택하면 작업마다 별도의 Git checkout을 만들 수 있다. worktree는 Git repo를 요구하며 기본 시작 방식과 handoff 동작은 local checkout과 구분된다. 병렬 chat은 자동으로 같은 checkout에서 안전하게 병렬 편집한다는 뜻이 아니므로, worktree 격리 개념을 함께 설명해야 한다. [Git worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees) · [Windows app parallel chats](https://learn.chatgpt.com/docs/windows/windows-app)
- **터미널·변경 검토:** integrated terminal과 프로젝트별 common actions를 제공한다. Git pane은 diff를 보여주고 inline comments를 Codex에 전달하며, hunk/file 단위 stage/revert, commit, push, PR 생성을 지원한다. Git 기능은 Git이 설치되고 저장소가 올바르게 인식되는 등 전제조건이 있다. [Local environments: Actions/Git tools](https://learn.chatgpt.com/docs/environments/local-environment) · [Windows app Git prerequisite](https://learn.chatgpt.com/docs/windows/windows-app)
- **권한과 승인:** local clients의 보안 경계는 permission/sandbox profile과 approval policy 조합이다. 일반 개념으로는 read-only, workspace write, danger-full-access가 있으며, sandbox가 파일쓰기·명령·네트워크 접근을 제한하고 approval policy는 제한 밖 작업을 언제 승인받을지 결정한다. 실제 옵션은 macOS/Windows/WSL, app/CLI 버전, managed policy에 따라 다르므로 화면에 보이는 토글을 보편적 기본값처럼 가르치지 않는다. [Permissions](https://learn.chatgpt.com/docs/permissions) · [Agent approvals & security](https://learn.chatgpt.com/docs/agent-approvals-security)
- **local environment UI:** 프로젝트 전용 setup scripts/common actions를 desktop settings에서 구성해 .codex에 둘 수 있다. setup script는 새 worktree 생성 때 실행될 수 있고, actions는 통합 터미널에서 수행된다. 설정 공유와 실행 환경의 OS 차이를 보여주는 구체 예로 교육적 가치가 있으나, 위치·UI는 제품 버전에 따라 바뀌는 구현 세부다. [Local environments](https://learn.chatgpt.com/docs/environments/local-environment)
- **교육에서 구분할 층위 (해석):** 승인·sandbox, 저장소 변경, diff 검토, 격리, 검증은 여러 local interface에도 적용되는 개념이다. 반면 sidebar, 버튼 위치, shortcut, worktree 생성 메뉴, 설정 패널은 앱별 UI 기억에 묶이는 지식이다. 안정적인 개념을 설명하고, 특정 화면 흐름은 캡처 날짜/버전과 함께 필요한 만큼만 보이는 편이 유지보수에 유리하다. 이는 기능 목록에서 도출한 교육 설계 해석이지 OpenAI의 공식 교육 권고가 아니다. UI와 기능 추가는 release note상 계속 발생한다. [Codex changelog](https://learn.chatgpt.com/docs/changelog)

## §23. Codex CLI

### 설치·플랫폼·실행 범위

- 공식 명칭은 **Codex CLI**이며, 터미널에서 대화형으로 실행하거나 **codex exec**로 script/CI에 넣는다. 현재 quickstart는 macOS/Linux, Windows, npm, Homebrew 설치 탭을 제공한다. 문서의 macOS/Linux standalone installer 예시는 **curl -fsSL https://chatgpt.com/codex/install.sh | sh**이며, 설치 명령과 배포 방법은 버전별로 바뀔 수 있으므로 실제 사용 시 공식 install 페이지를 다시 확인해야 한다. [Codex CLI quickstart](https://developers.openai.com/codex/cli)
- **Windows/WSL:** WSL2는 Linux-native toolchain 또는 WSL에 저장된 저장소에 쓰도록 공식 안내되어 있다. 현재 문서는 WSL2를 전제로 하고 WSL1은 CLI 0.115부터 지원하지 않는다고 한다. Windows desktop의 native agent와 WSL 안에서 별도로 실행한 Linux CLI는 기본적으로 config, 인증 cache, session history를 공유하지 않으며 CODEX_HOME을 명시적으로 연결할 수 있다. 설치/운영 설명에서 “Windows 지원”을 한 문장으로 뭉뚱그리지 말고 **Windows-native 앱/CLI 경로와 WSL2 CLI 경로를 분리**한다. [WSL guide](https://learn.chatgpt.com/docs/windows/wsl) · [Windows app: WSL and CODEX_HOME](https://learn.chatgpt.com/docs/windows/windows-app)
- **Windows 상태 문서 간 차이:** 현행 CLI quickstart는 Windows install 탭을 노출하고, 현행 Windows sandbox 가이드는 CLI와 IDE extension을 포함해 Windows Codex를 문서화한다. 반면 과거 Help Center CLI 소개에는 Windows가 experimental이며 WSL 필요할 수 있다고 쓰인 문구가 남아 있다. 연구 기준일에 현행 제품 가이드를 우선하되, 특정 Windows 설치법의 지원 등급은 공식 페이지와 버전을 확인한 후 교육자료에 기입한다. [현행 CLI quickstart](https://developers.openai.com/codex/cli) · [현행 Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox) · [구 CLI Help 안내](https://help.openai.com/en/articles/11096431)
- **저장소와 지침:** 저장소 디렉터리에서 codex를 시작하면 Codex가 현재 repository를 탐색·편집하고 설치된 프로젝트 도구를 실행한다. 프로젝트 루트와 현재 경로를 따라 AGENTS.md를 읽어 작업 지침을 적용하며, /init은 지침 파일의 출발점을 만들 수 있다. 어떤 계층의 지침이 적용되는지 이해하는 것이 긴 프롬프트를 반복하는 것보다 재현성 있는 설명에 유용하다. [Codex CLI](https://developers.openai.com/codex/cli) · [AGENTS.md discovery](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- **명령 실행·편집:** CLI는 local file inspection/editing, 설치된 build/test/tool command 실행, 진행 중 명령 및 diff 검사, 같은 세션에서 후속 작업을 지원한다. 기본 interactive loop는 승인/sandbox 정책을 따른다. [CLI usage](https://developers.openai.com/codex/cli)
- **Sandbox와 승인:** 사용자는 read-only, workspace-write, danger-full-access 같은 sandbox mode/permission profile 및 승인 정책을 조합한다. 기본 권장 Auto 흐름은 workspace 안 파일 수정과 실행을 허용하되 바깥 경로나 네트워크 접근에 승인 경계를 둔다(정책에 따라 달라짐). Windows native, macOS, Linux/WSL은 OS별 sandbox 구현이 다르다. danger-full-access/--yolo는 경계를 넓히거나 없애므로 일반적인 기본 설정처럼 소개하지 않는다. [Agent approvals & security](https://learn.chatgpt.com/docs/agent-approvals-security) · [Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)
- **웹/검색:** CLI에는 desktop app의 built-in browser UI가 없다. --search 또는 web_search = live로 Codex web search를 사용할 수 있으나 이는 CLI 안에 브라우저 탭과 동일한 browsing/Computer Use가 있다는 뜻이 아니다. 기본 web search 모드는 cached로 설정될 수 있다. shell commands의 outbound network는 별도 sandbox/network setting이다. [Browser availability](https://learn.chatgpt.com/docs/browser) · [Approvals: web search/network](https://learn.chatgpt.com/docs/agent-approvals-security) · [CLI web-search flow](https://developers.openai.com/codex/cli)
- **Skills:** standalone filesystem skills는 desktop app, CLI, IDE extension에서 지원된다. CLI에서 $skill-name을 직접 호출하거나 /skills로 확인할 수 있고, project/user/system 경로의 SKILL.md와 선택적 리소스·script로 반복 workflow를 만든다. Skill script도 현재 실행 권한/sandbox 경계를 따른다. [Build skills](https://learn.chatgpt.com/docs/build-skills)
- **Subagents/parallel:** interactive CLI session에서 독립된 조사·작업을 subagent에 위임하고 /agent로 agent thread를 확인·전환할 수 있다. parallelism은 독립적인 하위 작업 설계와 사용 가능한 모델/config/context에 달리며, write-heavy 작업을 동시에 돌리면 파일 충돌 위험이 있다. 병렬 agent 수를 무제한·항상 가능한 보장처럼 가르치지 않는다. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
- **Session 이어가기 / Desktop 연결:** codex resume은 현재 repo의 저장된 세션을 이어간다. 현재 CLI의 /app은 지원 macOS/Windows에서 같은 저장된 chat을 desktop app으로 연다. CLI와 IDE extension은 config.toml 설정 레이어를 공유하며 desktop app과 IDE extension도 동일 프로젝트에서 active chats/editor context를 공유할 수 있다. Windows WSL CLI는 기본 CODEX_HOME이 달라 별도 설정 없이는 Windows 앱의 인증·기록을 공유하지 않는다. 이 관계들을 “모든 interface가 같은 context를 자동 공유한다”고 일반화하지 않는다. [Developer commands](https://learn.chatgpt.com/docs/developer-commands) · [Developer settings / IDE sync](https://learn.chatgpt.com/docs/developer-settings) · [Windows app/WSL](https://learn.chatgpt.com/docs/windows/windows-app)
- **Non-interactive/automation:** codex exec는 TUI를 띄우지 않고 prompt를 실행하며 stdout/stderr/JSONL 형식, --sandbox, 세션 이어가기 등을 통해 CI·scheduled script·pipe workflow에 넣을 수 있다. OpenAI GitHub Action은 CLI를 설치하고 codex exec를 지정한 permission으로 호출한다. Credential과 approval을 unattended runner에서 어떻게 통제할지 별도 설정해야 한다. [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode) · [GitHub Action](https://learn.chatgpt.com/docs/github-action)

### 교육적 가치와 다른 표면과의 겹침

CLI는 모델이 실제 repository context를 읽고, 도구 명령을 실행하고, 변경을 diff로 만들며, 승인 경계를 만나는 지점을 터미널 로그로 따라가기 좋다. AGENTS.md·Skills·config·sandbox를 묶어 **Harness를 구성하는 규칙과 실행 권한이 interface를 넘어 어떻게 유지되는지** 설명할 근거가 된다. codex exec는 대화형 사용과 CI/자동화의 경계도 보여준다. 이 가치는 공식 제품 포지셔닝이 아니라 위 공식 CLI 기능으로부터의 교육 해석이다. [CLI](https://developers.openai.com/codex/cli) · [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) · [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)

Desktop과 CLI는 local repo, 명령 실행, approvals/sandbox, Skills, subagents 등 핵심 작업 능력을 공유한다. 차이는 모델 능력이라기보다 **상호작용 표면**(앱의 작업목록·시각적 diff/Git review vs. terminal-native command/scriptable interface)과 UI convenience에 있다. 교육 중복을 줄이려면 기본 workflow 개념을 한 번 설명하고, CLI에서는 자동화·재개·설정의 추가 표현만 비교하면 된다. 이 또한 source evidence를 바탕으로 한 해석이다. [Desktop Git/local env](https://learn.chatgpt.com/docs/environments/local-environment) · [CLI](https://developers.openai.com/codex/cli)

## §24. Codex IDE 통합과 다양한 개발자 대상성

### 공식 명칭·지원 IDE

- OpenAI 공식 용어는 **Codex IDE extension**이다. VS Code와 호환 editor에서는 OpenAI Codex extension을 쓰며 공식 quickstart는 Visual Studio Code, VS Code Insiders, Cursor, Windsurf를 나열한다. **Xcode와 JetBrains IDE는 VS Code extension을 설치하는 것이 아니라 각 IDE의 자체 Codex integration**이다. VSCodium은 현행 공식 지원 목록에 명시되어 있지 않으므로 공인 호환으로 추가하지 않는다. [OpenAI IDE guide](https://developers.openai.com/codex/ide)
- **Cursor 주의:** Codex extension은 Cursor 안에서 독립된 OpenAI agent experience로 동작한다. Cursor의 Chat, Agent, Tab/autocomplete, Cloud/Background Agents, model picker가 Codex extension으로 바뀌거나 ChatGPT 구독으로 구동되는 것은 아니다. extension은 eligible ChatGPT subscription 또는 OpenAI API key 인증을 지원한다. [Using OpenAI models in Cursor](https://help.openai.com/en/articles/20001506-using-openai-models-in-cursor)
- **JetBrains:** JetBrains AI Assistant 문서는 Codex를 third-party coding agent로 제공하며 IntelliJ IDEA, PyCharm, WebStorm, Rider 등 JetBrains 계열에서 AI Chat 안에 활성화한다. 인증은 JetBrains AI subscription, OpenAI API key 또는 provider OAuth 중 지원 경로를 따르며, 이용 가능성과 billing은 선택한 방식·IDE/AI Assistant 버전·조직 설정에 달려 있다. Codex가 .aiignore 기능을 따르지 않는 제한도 문서화돼 있다. [JetBrains Codex agent](https://www.jetbrains.com/help/ai-assistant/codex-agent.html) · [JetBrains agent activation matrix](https://www.jetbrains.com/help/ai-assistant/activate-agents.html)
- **Xcode:** Apple은 Xcode 26.3의 Coding Assistant에 OpenAI Codex agent를 내장 연동했다고 문서화한다. Codex는 project context를 바탕으로 작업하고 Xcode MCP tooling을 통해 build/test 및 Apple 문서 검색을 수행할 수 있다. 이는 VS Code extension 설치 흐름과 다른 Apple 플랫폼 전용 통합이다. [Xcode 26.3 release notes](https://developer.apple.com/documentation/xcode-release-notes/xcode-26_3-release-notes) · [Apple Xcode agentic coding](https://developer.apple.com/videos/play/tech-talks/111428/)

### IDE workflow, context sharing, portability

- **에디터 문맥:** Codex extension에서 열린 파일, 코드 selection, 최근 chat을 composer에 포함시켜 해당 파일을 설명·수정할 수 있다. 수정 결과의 요약 및 changed lines를 코드 옆에서 검토하며 후속 수정을 요청할 수 있다. [Codex IDE guide](https://developers.openai.com/codex/ide)
- **Local/Cloud:** IDE는 local work의 빠른 focused iteration 표면이며, 긴 작업은 Codex cloud로 이어서 보낼 수 있다. Cloud task가 완료되면 같은 editor workflow로 돌아와 결과를 검토하는 흐름이 문서화되어 있다. [Codex IDE guide](https://developers.openai.com/codex/ide) · [Codex cloud](https://developers.openai.com/codex/cloud)
- **Desktop/CLI context sharing:** desktop app과 IDE extension이 같은 project를 열어둔 경우 active chat과 editor context를 공유하고, app chat을 IDE에서 열거나 IDE chat을 app에서 이어갈 수 있다고 현행 settings 문서는 명시한다. CLI와 IDE extension은 agent configuration (config.toml)의 동일 계층을 공유한다. Desktop/CLI/IDE 전체가 모든 기록·화면 상태를 자동 동기화한다는 의미는 아니다. [Developer settings: IDE extension sync](https://learn.chatgpt.com/docs/developer-settings) · [Config basics](https://learn.chatgpt.com/docs/config-file/config-basic)
- **OS 및 permissions:** VS Code 계열에서 Windows 실행은 Windows native sandbox 또는 설정을 통한 WSL2 경로를 지원한다. Mac/Linux/Windows에 sandbox 경계가 있지만 구현은 OS별로 다르다. 특정 IDE extension 호환 버전이나 OS별 UI의 세부 표는 출시와 함께 달라질 수 있다. [Windows sandbox/IDE](https://learn.chatgpt.com/docs/windows/windows-sandbox) · [Agent approvals & security](https://learn.chatgpt.com/docs/agent-approvals-security)
- **Skills/subagents vs plugins:** standalone filesystem Skills와 subagents는 IDE extension에서 사용할 수 있다. Codex plugins는 현행 문서상 IDE extension에서 지원되지 않고 desktop app 또는 CLI를 사용해야 한다. 즉, “IDE에서 Codex 기능”과 “다른 local clients와 똑같은 전체 기능”은 동일하지 않다. [Skills](https://learn.chatgpt.com/docs/build-skills) · [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) · [Plugins support matrix](https://learn.chatgpt.com/docs/plugins)
- **다양한 개발자 교육에서의 활용 해석:** 회사 개발자들이 쓰는 IDE가 다양하면 특정 VS Code extension 화면을 공통 필수 과정으로 만들 경우 일부 참석자는 자기 환경과 다른 제품 UX를 보게 된다. 공통으로 설명할 핵심은 열린 repository context, 지침, 수정 제안, 실행/검증, diff review이며, IDE-specific 메뉴는 각 integration에 따라 다르다고 분리한다. VS Code extension을 대표 화면으로 쓸지는 참석자 IDE 분포와 운영 조건을 확인한 뒤 결정할 사항이다. 이는 교육 설계 추론이며 최종 Demo 선택이 아니다.
