# Prompt Engineering

## Research Question

Prompt Engineering은 어떤 문제를 해결하고 어디에서 한계가 생기는가?

## Why It Matters

Chatbot 사용자를 바로 Harness로 보내지 않고 질문·요구·제약을 명확히 하는 단계를 보여준다.

## Findings

- **Type: PRODUCT BEHAVIOR / Confidence: MEDIUM / Freshness: see Checked date for cited SRC IDs in SOURCES.md / Source: SRC-0114** — Codex prompting guidance supports clearer task framing and investigation-first requests.
- **Type: TEACHING MODEL / Confidence: HIGH / Freshness: see Checked date for cited SRC IDs in SOURCES.md / Source: SRC-0001** — Prompt Engineering is the first maturity step after simple chatbot use.
- **Type: HEURISTIC / Confidence: MEDIUM / Freshness: see Checked date for cited SRC IDs in SOURCES.md / Source: SRC-0139** — Before/After prompt comparisons should keep task, repo, model, environment, scoring stable where possible.

## What the Evidence Does NOT Prove

Better prompt alone does not remove missing repository context, tool permission, stale instructions, or verification gaps.

## Implication for Training

초급자가 “바로 고쳐줘” 대신 “먼저 조사하고 계획해줘”로 이동하게 한다.

## Risks / Caveats

Prompt, context, model, environment를 동시에 바꾸면 원인을 분리할 수 없다.
