# Feature / Concept Matrix

> Product Feature는 현재 OpenAI/Codex 제품에서 문서화된 기능 또는 surface다. Engineering Concept과 Training Model은 제품 기능이 아니며, 실제 demo 사용 여부는 target account, workspace policy, repository, verification command가 정해진 뒤 확정한다.

| Topic | Product Feature | Engineering Concept | Training Model | Evidence | Notes |
|-------|-----------------|---------------------|----------------|----------|-------|
| Prompt / Prompt Engineering | NO as a single Codex-only feature; official API guide defines prompt engineering and Codex docs provide prompting guidance. | Instruction design for an individual task's goal, context, constraints, expected behavior, and result conditions. | First maturity step; separate the task-framing candidate from the broader teaching checklist Goal/Context/Constraints/Process/Verification. | SRC-0144, SRC-0114, SRC-0001 | Official definition and training checklist are related but not identical. |
| AGENTS.md | YES: official Codex instruction artifact with nested discovery. | Repository instruction context. | Reduce repeated prompt instructions while preserving plan Source of Truth. | SRC-0110, SRC-0001, SRC-0002 | Not a substitute for `plan/`. |
| Context routing | NO as a single product feature; product provides multiple context channels. | Choosing which source goes to prompt, repository docs, AGENTS.md, Memory, tool output, or external research. | Teach context as selection and routing rather than “more tokens.” | SRC-0110, SRC-0113, SRC-0133, SRC-0201 | Related to Context Engineering; not a named official feature. |
| Progressive Disclosure | PARTIAL: OpenAI Skills docs use progressive disclosure for Skills loading; not standalone feature. | Reveal/load information only when needed to reduce irrelevant context. | Separate Skills loading pattern, context staging, and Problem-before-Solution teaching sequence. | SRC-0111, SRC-0001 | Do not claim general academic/industry consensus from current sources. |
| Skills | YES: reusable workflow unit where supported. | Procedure reuse and workflow packaging. | Introduce only after repeated friction. | SRC-0111, SRC-0117 | OQ-008. |
| Subagents | YES: separate agent threads where supported. | Delegation and context isolation. | Split independent work with risk-based checkpoints. | SRC-0112, SRC-0219 | Not always faster. |
| Parallel agents | PARTIAL: supported through subagents/parallel workflows where available. | Wall-clock, token, coordination, and conflict tradeoff. | Use only when tasks are independent enough to justify coordination cost. | SRC-0112, SRC-0219, SRC-0123 | Do not present as inherently better. |
| Memory | YES: Codex Memory where available. | Persistent preference/context channel. | Separate Memory from current Context and Source of Truth. | SRC-0113, SRC-0001 | OQ-005. |
| Persistent project knowledge | PARTIAL: can be represented through project docs, AGENTS.md, Memory, local env config; no single universal product feature. | Durable project facts and instructions that survive one prompt/session. | Keep canonical project knowledge in Source of Truth; use product features only as routing surfaces. | SRC-0110, SRC-0113, SRC-0135, SRC-0001, SRC-0002 | Avoid equating Memory with Source of Truth. |
| Tools | PARTIAL: tools include web search, commands, MCP/apps, hooks, graders, scripts depending on surface. | Callable capabilities that read or change external state. | Add tools to answer observed friction, not as a feature catalog. | SRC-0115, SRC-0116, SRC-0118, SRC-0124, SRC-0141 | Specify tool class instead of saying “tools” generically. |
| MCP | PARTIAL: supported where plan/admin/provider permissions allow. | External context/action protocol. | Optional Harness extension, not core Story dependency. | SRC-0116, SRC-0131 | OQ-014. |
| Build/Test | PARTIAL: command execution supports build/test only when repo/toolchain/setup exists. | Verification commands and executable oracle. | Use to move from AI answer to evidence. | SRC-0103, SRC-0105, SRC-0139 | OQ-007. |
| Verification | NO as a single product feature; supported by commands, diff review, evals, human review. | Confirm behavior through commands, tests, diff, review, evidence limits. | Core responsibility pattern across all stages. | SRC-0103, SRC-0105, SRC-0139, SRC-0140 | Test pass is not full correctness/security guarantee. |
| Worktree | YES: Codex worktree mode for Git repositories. | Isolation for parallel/change review. | Optional way to show safe parallel changes. | SRC-0123 | Not required for every Harness. |
| Harness | NO as a single product feature. | Context, tools, permissions, scripts, checks, workflow, feedback surfaces around an agent. | Minimum Effective Harness in response to observed friction. | SRC-0137, SRC-0206, SRC-0218, SRC-0001 | Do not mark as product feature. |
| Evaluation | YES/PARTIAL: OpenAI eval docs and agent eval workflows; exact product path depends on surface/API. | Task, criteria, dataset, grader, traces. | Distinguish illustrative demo from controlled evidence. | SRC-0139, SRC-0140, SRC-0212 | OQ-009. |
| Feedback Loop | NO as a single product feature; supported by eval/traces/automation materials. | Result evidence informs next prompt/context/harness/eval change. | Explain Loop as learning structure, not repeated execution alone. | SRC-0140, SRC-0222, SRC-0223, SRC-0224 | Human checkpoint remains risk-based. |
| Loop Engineering | NO as a single product feature. | Feedback-driven improvement cycle. | Harness → Loop: observe, diagnose, modify, re-evaluate. | SRC-0140, SRC-0222, SRC-0223, SRC-0224, SRC-0001 | Automation is only a material. |
| AI-Native Development | NO as a single product feature. | Operating model for agent-assisted software engineering. | Final maturity framing: developers keep Goal/Judgment/Verification/Responsibility while designing agent work systems. | SRC-0136, SRC-0225, SRC-0226, SRC-0001 | Candidate wording; not industry consensus. |
| ChatGPT GitHub connector | YES: ChatGPT can read/search authorized repositories where available. | Repository context source. | ChatGPT context use before Codex execution. | SRC-0133 | Read-only context; not write/push. |
| Codex repository work | YES: Codex CLI/Desktop/IDE/Cloud can work with repositories subject to surface and permissions. | Agentic coding workflow. | Move from pasted code to repository-aware work. | SRC-0101, SRC-0103, SRC-0104, SRC-0105 | Surface availability is high-volatility. |
| Web search | PARTIAL: supported search surface; not same as shell network/cloud internet. | External evidence gathering. | Prefer official/current sources for volatile facts. | SRC-0115, SRC-0124 | Search result is not truth guarantee. |
| Hooks | YES where supported by Codex/plugin environment. | Lifecycle automation. | Automation material, not Loop itself. | SRC-0118 | Use with caution. |
| `codex exec` / non-interactive mode | YES where CLI is available. | Repeatable command-line agent run. | Possible Loop/CI material. | SRC-0119 | Needs repo/eval design. |
| GitHub Action | YES where configured. | Triggered automation. | Possible later Loop material. | SRC-0120 | Requires repository permissions and secrets policy. |
| Local execution | YES: Local/Worktree files and commands run on user computer. | Environment-bound execution. | Show execution location as part of context. | SRC-0106, SRC-0135 | Does not mean inference is local-only. |
| Cloud execution | YES: configured Codex Cloud environment. | Isolated remote execution with setup. | Demo reproducibility candidate with pinned commit/setup. | SRC-0105, SRC-0106 | Company policy and repo access unresolved. |
| Code review | YES: Codex review and GitHub PR review contexts. | Human review and diff inspection. | Reinforce judgment/responsibility. | SRC-0121, SRC-0122 | Review output is not correctness guarantee. |
| Lost in the Middle | NO: academic finding, not product feature. | Long-context placement/retrieval caution. | Supports Context Engineering caveat. | SRC-0201, SRC-0202, SRC-0203 | Do not overgeneralize to all current models. |
| Data security and workspace policy | PARTIAL: product controls and data policies exist by plan/workspace. | Security boundary and governance. | Separate OpenAI product behavior from company allowance. | SRC-0125, SRC-0126, SRC-0127, SRC-0128, SRC-0129, SRC-0131 | OQ-014 remains open. |
