# Agent Evaluation

## Research Question

Agent evaluation evidence should constrain what we claim about Codex and Harness improvements?

## Why It Matters

Loop and Before/After demos need honest evidence practices.

## Findings

- **Type: PRODUCT PRACTICE / Confidence: HIGH / Freshness: see Checked date for cited SRC IDs in SOURCES.md / Source: SRC-0139, SRC-0140** — define task, success criteria, fixtures, metrics/graders, traces before claiming improvement.
- **Type: ACADEMIC FINDING / Confidence: HIGH / Freshness: see Checked date for cited SRC IDs in SOURCES.md / Source: SRC-0212** — agent evals can vary by run and consume large token/tool budgets.
- **Type: ACADEMIC FINDING / Confidence: MEDIUM / Freshness: see Checked date for cited SRC IDs in SOURCES.md / Source: SRC-0211, SRC-0221** — pass/fail can hide lucky passes and process failures.

## What the Evidence Does NOT Prove

No evaluation source here proves the training demo will improve productivity or that one run is representative.

## Implication for Training

Use illustrative demos for explanation; reserve causal claims for controlled comparisons.

## Demo Implication

Capture prompt, commit, environment, command, output, diff, run date, product surface.

## Risks / Caveats

Overfitting to tiny demo eval, flaky infrastructure, unsupported productivity claims.
