# Coding Agent Benchmarks

## Research Question

Coding-agent benchmark scores can support which claims and which claims must be avoided?

## Why It Matters

Benchmarks are useful but easy to overread as workplace productivity predictions.

## Findings

- **Type: ACADEMIC FINDING / Confidence: HIGH / Freshness: see Checked date for cited SRC IDs in SOURCES.md / Source: SRC-0206, SRC-0207, SRC-0208** — SWE-bench family evaluates issue-resolution-like tasks under specific harness/model/scoring conditions.
- **Type: ACADEMIC FINDING / Confidence: HIGH / Freshness: see Checked date for cited SRC IDs in SOURCES.md / Source: SRC-0206** — scaffold/interface changes can affect scores.
- **Type: FACT / Confidence: MEDIUM / Freshness: see Checked date for cited SRC IDs in SOURCES.md / Source: SRC-0209, SRC-0210, SRC-0143** — SWE-Bench Pro sources and audit material require version/source distinction.
- **Type: ACADEMIC FINDING / Confidence: MEDIUM / Freshness: see Checked date for cited SRC IDs in SOURCES.md / Source: SRC-0220** — sandbox resources can affect benchmark success and infrastructure errors.

## What the Evidence Does NOT Prove

Benchmark scores do not predict team workplace productivity, code quality, security, or maintainability without matching tasks/environments.

## Implication for Training

Use benchmarks to show why model, harness, task, resources, scoring must be named together.

## Demo Implication

Avoid live claims like “this model scores X so our demo will work.”

## Risks / Caveats

Leaderboards change; model/harness details may be incomplete.
