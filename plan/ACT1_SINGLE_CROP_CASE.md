## Educational request

```text
crop test 고쳐줘.
기존 명세와 테스트 기대값은 유지하고,
명세에 어긋난 crop 구현만 최소 수정해.
관련 테스트와 전체 테스트를 확인하고,
변경 내용·검증 결과·미확인 사항을 보고해.
```

crop(1,3)의 기대 열1·2와 폭2는 작은 참고 예시로 둔다. 앞 장에서 시작한
같은 사례이며 S20/S21의 분류표를 먼저 반복하지 않는다. 관련 테스트는
관련 동작을 골라 확인하는 것이고 실제 Trial의 관련3건을 crop만의3건으로 바꾸지 않는다.

## Boundaries

세 장 모두 교육용 요청·개념도다. 실제 TRIAL-002 원문이나 수행 결과가 아니다.
기존 명세·기대값이 유효한 이 사례에서는 구현을 명세에 맞춘다. 기대값 변경은
정당한 명세 변경과 승인이 있는 경우에 검토한다. Agent는 저장소 근거로 적절한
수정을 추론할 수 있고, 의도·명세가 충돌하면 질문할 수 있다.

토큰·작업 시간의 기존 PNG는 수치 없는 개념도다. 총 비용 증가·절감, 기하급수
법칙, 실제 Agent 정지·실패·내부 추론의 근거로 사용하지 않는다. 강조한 경로는
의도한 변경 범위이며 실제 선택·정확성·결정성·성공을 보장하지 않는다.

실제 TRIAL-002 발췌·번역, 수정·검증 결과는 그대로다. 새 Trial·비교 실험·제품
실행·현재 Desktop 검증은 하지 않는다. Demo 저장소·Site·발표 묶음은 변경하지 않는다.
