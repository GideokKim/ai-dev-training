# ACT4 개편안 — 한 번 맡긴 목표의 구현·검토·수정

**DEC-0160 · 2026-11-03 · 독립 검토에서 상태 인계로 연결**

S77의 점심 전후 대화에서 출발해 S79에서 사람이 첫 검토 지적을 다시 전달하는 상황과 S80에서 그 지적이 다음 수정으로 이어지는 상황을 비교한다. S81은 두 진행 방식을 정리하고, S82는 여섯 구성 역할, S83은 목표에서 사람 인계까지 여덟 작업 단계를 제시한다.

## S83의 8단계 워크플로우 원문

DEC-0157에 따라 아래 표는 발표 Notes의 설명 기준으로 보존한다. 화면에서는 단계 이름과 연결선을 따라 같은 작업이 어디서 반복되고 어디서 끝나는지 읽는다.

| 단계 | 하는 일 | 남기는 결과 |
|---|---|---|
| 1. 목표와 범위 정의 | 무엇을 바꾸고 무엇을 유지할지, 완료 기준을 정합니다. | 목표·제약·완료 기준 |
| 2. 현재 상태 조사 | 코드·명세·기존 변경 사항을 읽고, 문제나 현재 성능을 확인합니다. | 조사 결과·재현 결과·기준선 |
| 3. 계획과 실행 환경 준비 | 변경 순서와 검증 방법을 정합니다. 필요하면 Worktree와 Subagent를 준비합니다. | 작업 계획·역할·실행 조건 |
| 4. 구현 | 정한 범위 안에서 코드를 변경합니다. | 변경 코드·테스트 |
| 5. 실행 검증 | 빌드·테스트·벤치마크 등을 실행하고 기존 결과와 비교합니다. | 실행 결과와 근거 |
| 6. 독립 검토 | 요구사항 누락, 회귀 가능성, 테스트 부족을 별도 관점에서 검토합니다. | 검토 의견·남은 문제 |
| 7. 다음 행동 판단 | 보완할지, 완료할지, 중단하고 사람에게 확인할지 결정합니다. | 계속·완료·중단 판단 |
| 8. 결과 정리와 인계 | 최종 변경, 검증 결과, 미실행 항목과 후속 작업을 정리합니다. | 사람이 확인할 결과 보고 |

보완할 때에는 4단계 구현으로 복귀해 5–7단계를 다시 거친다. 완료 보고에는 변경과 검증 근거를, 미완료 인계에는 미실행 항목과 후속 확인을 함께 남긴다.

### 독립 검토에서 다음 실행으로

S89에 올린 병합 요청을 S90에서 두 역할이 주고받는 예시로 펼친다. 작성자는 행별 집계 변경과 출력 비교를 건네고 검토자는 최대 할당량을 확인할 재측정을 요청한다. S91에서 이 지적과 측정 조건을 다음 실행에 넘길 상태 기록으로 남긴다. 모델 이름과 요청은 이 역할을 읽기 위한 교육용 배치다. 기존 자기선호와 역할 귀속 연구의 원문·해석 한계는 [참고자료](../references/engineering/loop-engineering.md)에 보존한다.

### S97에서 읽을 Goal 입력 예시

> /goal 밝기 통계의 임시 메모리 사용량을 줄여줘. 기존 출력 6개가 같고, 같은 입력에서 기준판보다 최대 할당량이 낮으면 완료해. 측정할 수 없으면 중단하고 이유를 알려줘.

이전 실행 자료를 소재로 만든 요청이다. 이 /goal 입력의 실행과 측정 결과는 미검증이다. [Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)
