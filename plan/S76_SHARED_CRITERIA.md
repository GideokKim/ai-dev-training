# S76 — 여러 작업자가 공유하는 프로젝트 기준

Decision: DEC-0141. Date:2026-11-03. Baseline:`460b30a`.

## 현재 승인

S76 제목은 “누가 작업하더라도 프로젝트 기준은 같게”다.
같은 프로젝트에서 작업자 A/B/C가 각자의 AI에 조건을 따로 전달하는 경우와 공통 Harness로 기준을 공유하는 경우를 좌우 설계 비교로 보여준다.
왼쪽은 기준이 달라질 수 있다는 조건부 모습이다. 오른쪽은 명세·제약, 수행 절차, 검증·보고 기준을 공유하되 세 작업 경로와 결과물은 구분한다.
한 결과로 합치는 Subagent 그림, 동일 코드·자동 준수·자동 조율·측정 성과를 뜻하는 체크나 수치는 사용하지 않는다.

## 이전 의도 보존

이전 제목 “공통 기반에 프로젝트 기준을 연결한다”는 재사용 방법과 프로젝트 결합 지점을 구분하기 위한 설명이었다.
조사·변경·검증 흐름과 도구 연결·검토·보고 틀은 재사용하고, 프로젝트의 목표·명세와 실제 빌드·테스트·측정 명령/도구, 권한·실행 조건은 확인해 연결한다.
이 지식은 새 화면의 공통 기준을 실제로 적용하는 방법으로 S76 Notes의 Speaker Flow와 Advanced Insight에 유지한다.
프로젝트 정보와 수행 방법은 역할이 다르며, 사실 전체를 공통 지침에 복사하거나 문서 연결만으로 실행·준수가 보장된다고 보지 않는다.

## 앞뒤 연결과 시간

S75는 다른 프로젝트로 재사용할 기반, S76은 한 프로젝트의 여러 작업자가 공유할 기준, S77은 그 기반으로 한 목표를 구현·검토하는 반복 관계를 맡는다.
S75/S77 화면은 유지하고 연결 cue만 최소 정렬한다. S76 Lecture2분+Harness Q&A5분=7분을 유지한다.
전체113장·389분, ACT3 18장·64분, ACT4 20장·85분, 기존 ID·Section/Beat·Template·19Notes 필드를 유지한다.
명세·검증 기준의 일관성은 설계 목표이며 사람/Agent 비교 실험이나 편차 감소를 측정한 성과가 아니다.
기존 Evidence/Claim 원문과 원자료를 보존한다. 새 Trial·실측·제품 실행은 없다.
