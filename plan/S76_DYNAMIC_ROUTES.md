# S76 — 개별 요청 경로의 세 가상 위험

Decision: DEC-0143. Date:2026-11-03. Baseline:`729d773`.

## 승인 범위

S76 왼쪽의 작업자 A/B/C와 각자의 AI에서 출발하는 경로만 더 구체화한다.
A는 꼬불꼬불 우회한 뒤 검증 기준에 도달하고 “우회해서 도달”로 표시한다.
B는 검증 경계 전에 끊기거나 멈추며 “검증 전 중단”으로 표시한다.
C는 “기존 동작” 도식과 “기존 동작 훼손 위험”을 보여준다. 도착 경계는 “검증 기준”이다.
세 장면은 조건·절차·확인이 제각각일 때 생길 수 있는 위험을 설명하는 가상 TEACHING_MODEL이다.
실제 실패·파손 로그나 코드 변경, 사람/Agent 비교 실험 또는 위험 빈도를 보여주는 자료가 아니다.

## 보존

제목·작업자/AI·오른쪽 공통 Harness의 명세·제약/수행 절차/검증 기준과 분리된 결과는 유지한다.
공통 Harness가 자동 준수·동일 코드·검증 완료·성공을 보장한다고 말하지 않는다.
Harness가 없는 모든 작업이 실패한다는 의미도 아니다. 기존 Evidence/Claim 원문은 Notes에 그대로 보존한다.
목표·명세에 맞춰 실제 빌드/테스트/측정 명령·도구, 권한·실행 조건을 연결할 지식도 유지한다.

113장·389분, ACT3 18장·64분, S76 Lecture2+Harness Q&A5분=7분, ACT4 20장·85분은 그대로다.
ID·Section/Beat·Template·19Notes 필드를 유지한다. S75/S77의 현재 화면·연결 cue는 바꾸지 않는다.
새 Trial·측정·제품 실행·실제 프로젝트 파손은 없다. Demo 저장소·Sites·발표 묶음은 변경하지 않는다.
