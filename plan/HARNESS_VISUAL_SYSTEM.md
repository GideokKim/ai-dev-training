# Harness 관계·재사용·프로젝트 조립 시각 설계

Decision: DEC-0134. Date:2026-11-02. Baseline:`4ada660`.

## 승인 범위와 대상 확인

사용자의 네 시각 수정 주석을 현재 제목 기준으로 S75/S76/S77에 적용한다.
이전 대화에서 S77/S78로 부른 두 재사용 장은 현재 “만든 Harness를 다음 프로젝트의 기반으로”(S76),
“공통 기반에 프로젝트 기준을 연결한다”(S77)다. 현재 S78은 이번 수정 대상이 아니다.
119장·405분, 각 Slide ID·Title·Primary Role·Story Beat·Section·시간·Mode를 유지한다.
원래 S74의 실제 한 Agent 구성을 바꾸지 않는다. 삭제한 기존 감사 장을 복구하거나 Memory를 선행 설명하지 않는다.

## S75 — 함께 작동하는 작업 환경, Harness

기존 목표·Context·Skill→주 Agent→검증 도구와 사람의 검토, 공통 실행 환경을 유지한다.
주 Agent 아래 amber 점선의 작은 “선택 · 독립 조사” Subagent를 둔다.
주 Agent가 조사 범위를 맡기고 결과를 받아 확인·통합한다. 검증 도구의 근거·결과는 사람이 검토한다.
선택 Subagent는 Agent군에 종속된 요소이며 주요 입력/Agent/검증·검토/실행 환경의 계층을 흐리지 않는다.
점선·선택 라벨·배치로 선택성을 나타내고 색상만으로 근거 유형을 구분하지 않는다.

기존6분=Lecture4분+CAPTURED Demo2분을 유지한다.
Lecture는 과정의 Harness 모델과 선택 역할을 설명한다. 마지막2분은 실제 STATE-04-PERF의
목표·Context·Skill·한 Agent·검증·기록된 실행 조건만 대응한다.
선택 Subagent는 교육용 확장이며 실제 이 제품 상태에 추가·실행한 결과가 아니다.
실제 구성의 관찰과 관계 모델, 가능한 확장을 구분한다. 역할 분리의 속도·품질 효과를 새로 주장하지 않는다.

## S76 — 만든 Harness를 다음 프로젝트의 기반으로

왼쪽 큰 공통 Harness 모듈의 색·모양·내부 순서를 오른쪽 프로젝트 A/B/C 내부의 작은 모듈에 반복한다.
프로젝트 외곽 안에 모듈이 들어가도록 배치해 “같은 기반을 재사용한다”는 관계가 보이게 한다.
공통 모듈은 조사·변경·검증, 도구 연결, 보고 틀을 압축한 교육용 표현이다.
프로젝트별 조건은 다음 S77에서 연결한다. 수치·성공 체크·자동 이식/작동 보장은 넣지 않는다.
기존 Lecture2분과 Title·Primary Role을 유지한다.
“Audience Footer: 재사용 설계 예시” 문구를 제거하고 기존 M 연계는 유지한다.

## S77 — 공통 기반에 프로젝트 기준을 연결한다

같은 Harness 모듈 + 프로젝트 Context 문서 → 프로젝트 작업 시스템의 native3영역 그림을 사용한다.
문서에는 목표·명세, 실제 빌드/테스트/측정 명령, 권한·실행 조건을 구분해 배치한다.
조립된 시스템에서 주 Agent의 작업과 검증/검토 책임이 읽히도록 연결한다.
공통 수행 틀을 재사용하되 실제 프로젝트 조건을 연결해야 한다는 역할을 유지한다.
시각적 명료함은 일관된 모듈·문서·조립 관계에서 얻고 측정 성과나 완성/성공 판정으로 표현하지 않는다.
기존 Lecture2분과 Title·Primary Role을 유지하고 S78의 성공 범위/다음 작업 질문으로 잇는다.

## Template와 근거 경계

- S76: 기존 T03-A. 공통 모듈이 프로젝트 내부로 재사용되는 관계다.
- S77: 기존 T03-A. 이전 T04-A의 두 영역 비교를 세 영역 조립으로 바꾸며 새 Template/Variant를 만들지 않는다.

12Templates/28Variants는 그대로다. 현재 Template 배정 수는 T03 57장, T04 16장이고 전체119장이다.

다른 프로젝트에서의 실제 이식·자동 실행·성공·성능 또는 시간 절감은 관찰한 결과가 아니다.
새 Trial·실제 Subagent 실행·Memory 저장/회수·현재 제품 동작을 추가 주장하지 않는다.
