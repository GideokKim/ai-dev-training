사용자는 앞선 분석의 방향대로 ACT4를 개선하도록 승인했다. 작업 수행 루프와

현재115장·406분과 ACT4 S82–S100의19장·81분을 유지한다. 모든 Slide/Beat/

12Templates/28Variants,19Notes 필드, 기존 이미지와 Native 표·차트도 유지한다.
ACT4의 구간을 압축하거나 다른 ACT의 시간을 가져오지 않는다.

## 정의와 교육 범위

Loop Engineering의 일반 용례는 하나의 표준 분류로 확정되지 않았다. 이 교육은
기존 DEC-0023의 `실행 → 관찰 → 원인 판단 → 시스템 변경 → 재평가`를
체계 개선 중심의 운영 모델로 유지하며 두 범위를 명시한다.

- **작업 수행 루프:** 목표·검증 기준을 바탕으로 실행하고 결과에 따라 필요한
  수정·재검증을 거쳐 이번 작업을 완료한다. 모든 실행에 수정이 필요한 것은 아니다.
- **체계 개선 루프:** 수행 기록과 사람의 보정을 근거로 원인과 반복 필요를
  판단하고 지침·Skill·검증 기준 등 관련 출처의 변경 후보를 만든다. 같은 작업과
  대표 작업으로 영향을 재평가한 뒤 검토된 내용을 다음 실행에 반영한다.

ACT4는 후자에 무게를 둔다. 두 범위는 실무에서 겹칠 수 있으며 Harness에 원래
피드백이 없거나 Loop가 Harness를 대체했다는 역사적 주장을 하지 않는다.
완전자율화·모델 가중치의 학습·특정 제품의 자동 실행이 정의의 필수 조건은 아니다.
반복 실행만 설정했다고 이 교육의 체계 개선 루프가 완성되는 것도 아니다.

## 평가 뒤 선택과 남길 상태

| 조건 | 다음 행동 | 다음으로 넘길 것 |
|---|---|---|
| 기준 충족 | 작업 완료; 검토한 변경의 채택 | 확인 범위·검토된 기준·남은 한계 |
| 미충족이며 수정 가능 | 원인·범위를 재검토하고 재시도 | 시도한 변경·실행/검사 결과·새 평가 근거 |
| 근거 부족 또는 한도 도달 | 중단하고 추가 조사/사람의 판단 요청 | 시도·실행 조건·미해결 사항·확인할 질문 |

변경이 필요하지 않으면 현재 방식을 유지한다. 실패마다 새 규칙을 추가하지 않는다.
반복·시간·비용 한도와 판단 책임은 운영 설계에서 정할 대상이며 이 교육은 수치나
자동 집행 기능을 확정하지 않는다. 현재 요청의 중단과 문제의 완전 해결을 구분한다.
기록은 기존 문서/검사 로그/보고로 남길 수 있으며 별도 Memory 시스템을 요구하지 않는다.

## 평가 자료의 구체화

S91은 검증을 했다는 보고만으로 끝내지 않고 요청·적용 지침과 실제 실행 명령,
검사 로그·최종 보고를 대조하도록 설계한다. S92의 EVAL-01 버그는 명세/검사,
EVAL-02 성능은 측정 조건/결과·동작 확인, EVAL-03 문서는 요청 범위/불필요 절차,
EVAL-04 리팩터링은 보존 조건/변경·검사 기록을 비교할 대상으로 둔다.
이 네 가지는 모든 프로젝트의 고정 평가 세트가 아니다.

## 실제 사례와 미확인 범위

- STATE-04-PERF의 실제 밝기 통계 성공은 해당 입력·코드·환경·검증 범위만 보존한다.
- DEMO-04A는 별도 가상 사례다. 원인 확인·지침 수정·재실행·완료·채택·중단의
  실제 결과를 만들지 않는다. EVAL-01/02의 별도 과거 참고를 새 지침 평가에 합치지 않는다.
- 네 EVAL 모두 가상 지침 변경 뒤 실행 결과가 없으며 EVAL-03/04는 설계만 있다.
- S94의 분기는 제품이 지원하거나 자동 집행된 동작이 아닌 교육용 운영 설계다.
- TRIAL-006→DEC-0016→TRIAL-007/008은 실제 교육 Demo의 평가·보고 기록이다.
  Prompt만의 효과를 분리할 수 없다는 판단은 원인 확정과 다르다. 후속 확인은
  부분적이며 보고/원문 불일치, 환경 목록의 완전성, 품질 향상은 미확인이다.
- S99의 불일치→대조/검사 방법 재검토는 **다음 개선 질문 / 제안·미실행**이다.
  실제 후속 수정·개선 결과·자동 재시도·중단 이력을 추가하지 않는다.
- S100은 가상 GPU 적용 설계이며 실제 하드웨어 실행·성능 변화·기준 적용이 아니다.
