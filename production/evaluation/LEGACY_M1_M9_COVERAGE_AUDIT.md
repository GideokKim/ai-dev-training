**M1–M9가 현재 80장에 전부 들어 있지는 않다.** 요청 구체화, 공통 Context,
작은 코드 변경, 검증·측정, 개발자 책임은 이어진다. 리서치/보고서, 제품 시스템

`Chatbot → Prompt → Context → Harness → Loop → AI-Native Development`의
하나의 Repository 중심 Story로 재구성되어 있다. 다음 표의 SIDs는 관련 원칙의
위치이며, 그 번호만으로 원 모듈을 이수할 수 있다는 뜻이 아니다.

## 5. 현재 80장별 역방향 대응표

아래는 **현재 Slide가 구자료의 무엇과 연결되는가**를 보여준다. `일부`,
`원칙만`, `신규 확장`은 구 모듈 전체 반영 판정이 아니다. Notes만의 도구
언급은 별도로 표시한다. 현재 수업 자체의 좋은/나쁜 정도를 평가하는 표가 아니다.

## 6. 비교 후 남는 범위 차이

- **화면·Notes 모두 없는 구체 영역:** 입력 자료 보안/익명화, 도구 비교/설치,
  명명된 Prompt 기법·구조화 출력·업무 템플릿, 리서치/보고서 작성 방법,
  요구/제품 아키텍처/ADR, 신규 함수 생성·RAII·PR 리뷰, 테스트 작성/Mock/E2E,
  제품 장시간 장애, 운영 문서, AI 학습/온보딩, 업무 자동화 분류/HAL/CI/CD,
  SPACE/DORA와 기술 의사결정 TCO/KPI/ICE.
- **명시적으로 이어지는 중심 원칙:** 작업의 목표·제약·근거를 정하고,
  생성과 완료를 구분하며, 작은 변경과 실제 확인으로 판단하고 사람이 책임진다.
- **형태를 바꿔 확장한 영역:** 팀 공통 Context를 AGENTS.md/상세 문서로 유지,
  반복 절차를 repository Skill로 재사용, 필요한 Harness 구성만 선택,
  오래된 지침과 실제 평가 체계를 구분해 개선하는 Loop.
- 구자료의 직접 실습·PR 제출 과제는 현재 수업에 없다. 이는 현재 확정된
  `직접 실습 없음` 및 자발적·개인 성찰 방식과 구분해야 한다.
