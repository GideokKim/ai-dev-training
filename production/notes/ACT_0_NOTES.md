## S01 — AI에게 지금 무엇을 맡기고 있는가?

Slide ID: S01

Working Title: AI에게 지금 무엇을 맡기고 있는가?

ACT / Section: ACT 0 / 0A

Allocated Time: 5 minutes

Mode Split: Lecture 1 minute + Reflection 4 minutes

Primary Message: 자기 AI 활용을 평가하지 않고, 현재 맡기는 업무 범위를 돌아본다.

Opening Question: “나는 지금 AI에게 무엇을 맡기고 있는가?” 화면의 한 줄 안내처럼 최근 AI에 맡긴 일 하나를 떠올리게 한다.

Speaker Flow: 1. **OPEN (0:00–0:15 / Lecture):** 기존 제목과 “최근 AI에 맡긴 일 하나를 떠올려보세요”를 읽는다. 사용 수준을 평가하는 자리가 아니며 익숙한 경험 하나면 충분하다고 말한다.
2. **THREE CASES (0:15–0:45 / Lecture):** 같은 인물이 등장하는 세 장면을 각각 약 10초씩 가리킨다. “설명받기”에서는 코드 설명을 질문하는 장면, “조사맡기기”에서는 파일과 돋보기로 필요한 근거를 찾는 장면, “결과확인”에서는 변경 코드와 확인 근거를 함께 살피는 장면을 짧게 짚는다. 세 장면은 경험의 예시이며 서열이나 필수 발전 단계가 아니다.
3. **INVITE (0:45–1:00 / Lecture):** 이 중 최근 자신의 경험과 가까운 일 하나만 조용히 떠올리면 된다고 안내한다. Prompt·Context·Harness·Loop의 이름이나 성숙도 설명을 덧붙이지 않는다.

## S02 — 작은 질문에는 Chatbot이 유용하다

Slide ID: S02

Working Title: 작은 질문에는 Chatbot이 유용하다

ACT / Section: ACT 0 / 0B

Allocated Time: 5 minutes

Mode Split: Lecture 5 minutes

Primary Message: 필요한 코드나 오류를 전달해 답을 받는 방식은 작은 질문에서 빠르고 유용할 수 있다.

Opening Question: “괄호만 바꾸면 같은 원소가 만들어질까?” `std::vector<int>`의 두 초기화 표현을 작은 코드 질문으로 제시한다.

Speaker Flow:

1. **OPEN (0:00–0:45):** `std::vector<int> a(3, 1);`과 `std::vector<int> b{3, 1};`을 보여 준다. 같은 숫자라도 괄호가 다르면 어떤 의미가 되는지 묻는 교육용 예시임을 밝힌다. 실제 ChatGPT 대화나 컴파일 실행 화면이 아니다.
2. **COMPARE (0:45–2:15):** 이 `int` 예제에서 `(count, value)`는 값 1인 원소 세 개, 즉 `1, 1, 1`을 만든다는 의미를 짚는다. `{initializer_list}`는 나열한 값 `3, 1`을 담아 원소 두 개라는 뜻이다. 원소 도식은 코드의 의미를 설명하며 실행 출력으로 제시하지 않는다. 생성자 선택 전반이나 중괄호의 보편적 우월성을 강의하지 않는다.
3. **FOLLOW THE FLOW (2:15–4:15):** 연결된 세 노드에서 IDE의 “코드 선택·복사” → Chatbot의 “붙여넣고 질문” → IDE의 “답 확인·적용”을 각각 약 40초씩 짚는다. 필요한 코드와 질문의 범위를 사람이 고르고, 받은 설명이 원래 코드·요청과 맞는지 확인해 적용하는 흐름이다. 자동 IDE 연동이나 실제 코드 변경을 보여 주는 화면이 아니다.
4. **INTERPRET (4:15–4:30):** 작은 코드 조각의 혼동을 풀 때 이 질문 방식이 유용할 수 있음을 인정한다.
5. **TRANSITION (4:30–5:00):** 질문이 여러 파일과 구현 경로로 커지면 무엇부터 찾아 전달해야 하는지 S03으로 연결한다. 현재 방식을 잘못된 사용법으로 평가하지 않는다.

Evidence / Source: BEAT-001, CLM-0001, CLM-0002. TEACHING_MODEL / CONCEPTUAL. `std::vector<int> a(3, 1);` → `1, 1, 1`(3개), `std::vector<int> b{3, 1};` → `3, 1`(2개)는 코드 의미를 설명하는 도식이며 실제 실행·ChatGPT 응답·새 Trial이 아니다. C++ 의미 확인: [Microsoft Learn — vector constructors](https://learn.microsoft.com/en-us/cpp/standard-library/vector-class?view=msvc-170#vector), [Microsoft Learn — Initializers](https://learn.microsoft.com/en-us/cpp/cpp/initializers?view=msvc-170), 확인 2026-10-21. IDE → Chatbot → IDE는 사람이 연결하는 교육용 native 도식이다.

Claim Boundary: 일반적인 활용 예시이며 특정 제품 기능·정확도·성능 또는 다른 방식보다 우월하다는 주장으로 말하지 않는다. 초기화 비교는 화면에 제시한 `std::vector<int>` 두 표현의 의미로 한정한다. 도식은 실제 컴파일·실행 결과나 ChatGPT 대화가 아니며, 모든 중괄호 초기화가 같은 생성자 선택을 한다고 일반화하지 않는다. 코드 선택·복사, 대화에 붙여넣고 질문, IDE에서 답 확인·적용은 사람이 잇는 흐름이며 자동 IDE 연동을 뜻하지 않는다.

Beginner Explanation: 괄호만 다른 짧은 코드도 뜻을 물어볼 만한 질문이다. 두 표현이 각각 어떤 원소를 만드는지 설명을 받고 원래 코드와 맞는지 확인할 수 있다.

Advanced Insight: 익숙한 C++ 코드의 생성자 선택도 작은 질문의 대상이다. 이 장의 초점은 문법 강의보다 개발자가 필요한 Context를 선택·전달하고 답을 확인하는 흐름에 있다.

C++ Vision Bridge: 일반적인 C++ 코드 질문을 출발점으로 사용한다. 실제 Vision 처리·특정 IDE/컴파일러/Windows 빌드 조건·장비 실행을 추가하는 Demo가 아니다.

Demo Operation: N/A. 두 초기화 표현과 원소 도식, IDE → Chatbot → IDE의 연결된 native 흐름을 설명한다. 실제 대화·IDE 자동 연동·컴파일 실행·새 Trial은 없다.

Audience Interaction: Opening question은 생각을 여는 질문이다. 코드 작성·실행·손들기·경험 발표나 답변을 요구하지 않는다.

Transition: 질문이 여러 파일·구현 경로로 커지면 무엇을 먼저 찾아야 하는지 S03에서 묻는다.

Time Management: Lecture 5분 유지. 질문 45초, 초기화·원소 비교 90초, 연결된 세 노드 2분, 작은 질문의 가치 15초, S03 연결 30초로 운영한다. 상세 Prompt 작성법이나 C++ 초기화 문법 전반을 추가하지 않는다. 실제 발화 시간은 미측정이다.

Fallback: 공식 정적 경로 `production/ACT_0.pptx` S02 또는 `production/preview/act0/S02.png`의 두 C++ 표현·원소 비교·연결된 세 노드를 설명한다. 이번 수정본과 PNG의 일치 여부는 제작 단계에서 확인한다. 실제 ChatGPT 대화나 즉석 제품 화면으로 대체하지 않는다.

Validation Status: ALIGNED — DEC-0034에 따라 원문·Claim 경계와 제작용 화면/운영 지침을 정렬했다. 이번 수정본의 PPT 내장 Notes·최종 PNG 대조와 실제 렌더링 검토 결과는 `production/evaluation/ACT_0_OPENING_REVISION.md`에서 별도로 기록한다. 문서 정렬은 새 제작본의 렌더링 PASS나 실환경 검증을 뜻하지 않는다. Windows PowerPoint·실제 발표 PC 글꼴·교육장 투사·제품/계정·실측 리허설은 UNVERIFIED.

## S03 — 질문이 커지면 Context를 모으는 일이 생긴다

Slide ID: S03

Working Title: 질문이 커지면 Context를 모으는 일이 생긴다

ACT / Section: ACT 0 / 0C

Allocated Time: 4 minutes

Mode Split: Case 4 minutes

Primary Message: Repository 수준 질문에서는 사람이 관련 구현, 호출 경로, 테스트 결과와 명세서 등 필요한 정보를 찾아 대화에 옮기는 일이 생길 수 있다.

Opening Question: “디버깅할 때 우리는 어떤 정보를 살펴보고 있었을까?” 익숙한 Visual Studio 사용 상황을 떠올리게 한다.

Speaker Flow:

1. **OPEN (0:00–0:30):** 결과가 기대와 다를 때 여러 파일과 정보를 살펴보는 익숙한 상황으로 질문의 범위를 넓힌다. 실제 장애나 Trial 실패를 재현하는 화면이 아니다.
2. **SHOW IN PARALLEL (0:30–2:30):** 2×3 병렬 도식의 “테스트 탐색기 / 호출 스택 / 소스·참조 / 지역 변수·조사식 / 출력·로그 / 명세서”를 각각 약 20초씩 가리킨다. 실패 조건·기대값/실제값, 여기까지 온 함수, 구현/호출부, 멈춘 시점의 값, 빌드/실행 메시지, 원래 기대한 동작과 조건이라는 서로 다른 정보를 짚는다. 명세서는 외부 문서도 포함하며 IDE 내부 창이라고 설명하지 않는다. 여섯 영역은 실제 조사 순서나 모든 업무의 필수 체크리스트가 아니다.
3. **INTERPRET (2:30–3:30):** “이 정보 하나하나가 Context다”라는 핵심 메시지를 묶는다. 사람이 질문에 필요한 정보와 파일을 골라 대화로 옮기는 일이 생길 수 있음을 설명한다. Agent가 이를 대신한다는 해결책은 아직 공개하지 않는다.
4. **TRANSITION (3:30–4:00):** “파일명을 알려주지 않아도 Agent가 필요한 경로를 찾을까?”라는 S04의 관찰 질문으로 이동한다.

Evidence / Source: BEAT-002, CLM-0004, CLM-0009. TEACHING_MODEL / CONCEPTUAL. Visual Studio 사용자가 디버깅 때 참고하는 정보 범주를 병렬로 재구성한 교육용 native 도식이다. 실제 IDE screenshot·특정 제품 버전의 UI·특정 Trial의 파일 접근 또는 실행 기록이 아니다. 종이 문서를 든 인물 삽화는 이 수정본에서 사용하지 않는다.

Claim Boundary: ACT 0의 문제 모델이다. 특정 Trial의 실제 실패·관찰 순서·모든 Repository 업무에서 반복되는 비용으로 주장하지 않는다. 여섯 정보 범주가 모두 동시에 필요하다고 일반화하지 않는다. 명세서는 기대 동작을 확인하는 문서라는 뜻이며 실제 회사 문서나 제품 UI를 재현하지 않는다.

Beginner Explanation: 디버깅하면서 이미 보던 테스트 결과·코드·변수 값·명세서가 질문에 필요한 Context가 될 수 있다. 필요한 정보를 골라 묶는다는 점을 알아차리면 충분하다.

Advanced Insight: 코드 외에도 런타임 상태, 기대 동작과 입력 조건을 Context로 모으는 일이 별도 부담이 될 수 있다. 병렬 정보 범주는 실제 호출 순서·고정된 조사 절차와 구분한다.

C++ Vision Bridge: C++/Visual Studio 사용자에게 익숙한 디버깅 정보 범주를 활용한다. 특정 메뉴·버전·빌드·하드웨어 조작 절차나 실제 C++ 실행을 입증하는 예시는 아니다.

Working Title: 코드를 AI에게 가져가는 대신 AI를 Repository로 데려간다

ACT / Section: ACT 0 / 0E

Allocated Time: 3 minutes

Mode Split: Lecture 3 minutes

Primary Message: Repository 조사는 개발자가 코드를 일일이 전달하는 대신 Agent가 사용 가능한 Context를 찾도록 할 수 있다.

Opening Question: “Context 수집의 일부를 누가 맡을 수 있는가?”

Speaker Flow:

1. **CALL BACK (0:00–0:30):** 왼쪽 Repository → 개발자 선택·복사 → AI 관계로 S02를 짧게 회수한다.
2. **TRANSFER (0:30–1:30):** 오른쪽 개발자 조사 요청 → Agent ↔ Repository로 시선을 옮긴다. 바뀌는 것은 Context를 찾는 주체의 일부이며 목표와 검증 책임을 전부 넘긴다는 뜻이 아니다.
3. **ACCESS BOUNDARY (1:30–2:15):** Repository를 연결하거나 자료를 전달하기 전에 승인된 도구·계정, 입력 가능한 자료와 허용된 접근 권한 범위를 먼저 확인한다고 설명한다. 회사의 실제 허용·금지 목록과 승인 절차는 이 자료에서 확정하지 않았으므로 해당 조직의 정책을 확인해야 한다. 새로운 제품 설정이나 정책 목록을 가르치지 않는다.
4. **TRANSFER / TRANSITION (2:15–3:00):** 필요하면 큰 C++ 저장소에서도 모듈·테스트·계약을 찾는 상황을 한 문장으로만 연결한다. Repository 접근이 원하는 Task를 정하지는 않는다는 S08 질문으로 이동한다.

Evidence / Source: DEMO-01 / TRIAL-001 단일 CLI 관찰; BEAT-003, CLM-0002, CLM-0009. 본문은 Context 수집 역할을 비교하는 TEACHING_MODEL이며 하단에 연결된 과거 관찰의 범위를 별도로 표시한다. 삽화 출처: prototype/image-illustration-pilot/assets/S07.png, built-in image_gen, 2026-10-18. 생성 프롬프트: prototype/image-illustration-pilot/PROMPTS.md. 실제 화면·현장 사진·관찰 자료가 아니다.

Claim Boundary: 이 관찰은 CLI 한 번에 한정되며 제품의 보편적 성능·반복성 주장이 아니다. Repository 접근이 Task 의도나 성공을 자동으로 정한다는 뜻이 아니다. 도구·계정·자료·접근 권한의 사전 확인은 교육용 판단 지침이며 특정 회사의 허용·금지 정책이나 현재 제품의 보안 보장을 확인한 결과가 아니다.

Beginner Explanation: 관련 코드를 모두 복사하기보다 Repository 조사를 요청할 수 있는 가능성을 본다.

Advanced Insight: Context 수집 책임의 일부와 Task 목표·판단 책임을 분리한다.

C++ Vision Bridge: CONTEXTUAL speaker cue — 큰 저장소의 모듈·테스트·계약을 찾는 상황을 필요할 때 한 문장으로 연결한다. 화면에 도구·빌드·hardware 목록을 추가하지 않는다.

Demo Operation: DEMO-01 bounded callback. 본문 삽화는 교육 모델이고 새 제품 동작 관찰이 아니다. S05에서 본 단일 CLI 기록을 근거로 한 가능성을 설명하며 새 UI나 실행을 보여 주지 않는다.

Audience Interaction: 별도 질의 없음. 청중이 Mental Shift를 비교해 볼 수 있도록 잠시 시선을 둔다.

Transition: “Repository 접근과 Task 의도는 같은가?”라고 물으며 S08에 간다.

Time Management: 좌·우 관계의 변화에 집중한다. Trial 상세와 수치를 반복하지 않는다. 기존 관계 재설명과 선택적 C++ 해설을 줄여 접근 범위 확인 45초를 배치한다. C++ 연결은 선택적인 한 문장에 한정하고 Lecture 3분 안에 S08로 이동한다. 실제 시간 적합성은 리허설 전까지 UNVERIFIED다.

Fallback: Trial record를 표시할 수 없으면 Mental Shift만 Teaching Model로 설명한다. 제품 전반의 사실처럼 말하지 않는다. 정적 파일: production/preview/act0/S07.png 및 production/preview/full/S07.png.

Validation Status: REVIEWED — 사용자 승인 삽화를 전체 제작본에 반영했다. PPT/Notes/PNG 대조와 S72 잘림 재검토 결과는 production/evaluation/FULL_DECK_IMAGE_INTEGRATION.md에 기록한다. Windows PowerPoint, 발표 PC 글꼴, 교육장 투사, 실제 시간 리허설은 UNVERIFIED.

## S08 — Repository 접근과 Task 의도는 별개다

Slide ID: S08

Working Title: Repository 접근과 Task 의도는 별개다

ACT / Section: ACT 0 / 0E

Allocated Time: 2 minutes

Mode Split: Lecture 2 minutes

Primary Message: Repository 탐색은 Context 수집에 도움을 줄 수 있지만, Task의 목표와 완료 조건까지 대신 정하지 않는다.

Opening Question: “Repository를 볼 수 있으면 원하는 작업도 알게 되는가?”

Speaker Flow:

1. **OPEN (0:00–0:30):** 왼쪽 “볼 수 있는 것”과 오른쪽 “정해야 하는 것”을 분리한다.
2. **EXPLAIN (0:30–1:30):** 파일·구현·테스트가 보여도 원하는 변화, 허용 범위, 완료 판단은 별도로 전달해야 한다는 구분만 설명한다.
3. **TRANSFER (1:30–2:00):** 가운데 ≠를 짚고 “코드가 보여도 원하는 일은 따로 전달해야 한다”로 정리한다. 이어 이 구분을 각자가 맡기고 싶은 작업에 대입할 질문을 남긴다. ACT 1의 구체적인 요청 구조는 아직 소개하지 않는다.

Evidence / Source: BEAT-003 next friction, DEMO-01 callback, TRIAL-001; CLM-0002, CLM-0009. TEACHING_MODEL.

Claim Boundary: Mental Model이며 모든 제품·환경의 기능 설명이 아니다. Prompt 구조나 완료 조건의 구체 항목은 ACT 1에서 미리 설명하지 않는다.

Beginner Explanation: Agent가 Repository를 읽을 수 있어도 원하는 결과는 개발자가 말해야 한다.

Advanced Insight: Context access와 objective/acceptance responsibility는 별도 경계다.

C++ Vision Bridge: N/A.

Demo Operation: N/A — DEMO-01 성공 뒤 남는 문제를 설명한다.

Audience Interaction: Opening question은 수사 질문이다. 짧은 강의 시간에 답변을 요구하지 않는다.

Transition: “이 구분을 여러분이 지금 맡기고 싶은 일에 대입해 보겠습니다.”라고 S09의 개인 적용 질문을 연다.

Time Management: Access와 Intent 두 축만 설명하고 ACT 1의 구조나 목록은 소개하지 않는다.

Fallback: 화면 도식이 보이지 않으면 두 책임의 차이를 말로 한 번 설명하고 S09로 간다.

Validation Status: REVIEWED — 원문·Claim 경계, 화면의 설명 순서와 운영 지침을 대조했다. 최종 PPT/Notes/PNG 대조 결과는 production/evaluation/FULL_DECK_PRESENTATION_REVISION.md에 기록한다. Windows PowerPoint, 발표 PC 글꼴, 교육장 투사, 실제 시간 리허설은 UNVERIFIED.

## S09 — Repository를 보면 내가 원하는 것까지 알까?

Slide ID: S09

Working Title: Repository를 보면 내가 원하는 것까지 알까?

ACT / Section: ACT 0 / 0F

Allocated Time: 6 minutes

Mode Split: Transition 3 minutes + Q&A 3 minutes

Primary Message: Repository를 볼 수 있다는 사실만으로 Task의 의도가 정해지지는 않는다.

Opening Question: “내가 지금 맡기고 싶은 일의 원하는 결과까지 코드에 적혀 있을까?”

Speaker Flow:

1. **DISCUSS / TRANSITION (0:00–3:00):** 화면 상단의 “내 작업에 적용할 질문”을 짚고, 각자가 지금 맡기고 싶은 일 하나를 떠올리게 한다. “지금 이 저장소에 어떤 일을 맡기고 싶은가?”와 “그 원하는 결과까지 코드에 적혀 있는가?”를 차례로 읽는다. S08의 구분을 자기 작업에 대입하며 답이나 다음 단계의 체크리스트를 제시하지 않는다.
2. **Q&A (3:00–6:00):** 자발적인 질문을 받는다. 질문이 없으면 두 질문을 그대로 남긴 뒤 ACT 1의 모호한 요청으로 이동한다.

Evidence / Source: BEAT-003 → BEAT-004, TRANSITIONS.md의 승인된 ACT handoff, DEMO-01 callback, CLM-0002, CLM-0009. TEACHING_MODEL.

Claim Boundary: 이 장은 다음 문제를 여는 Teaching Model이다. ACT 1의 다섯 Task Specification 책임이나 구체적 해답을 공개하지 않는다.

Beginner Explanation: Repository 접근이 생긴 뒤에도 원하는 결과를 설명할 문제는 남아 있다.

Advanced Insight: 관찰 가능한 Context와 개발자가 정해야 할 의도를 구분하며 다음 Story 단계로 이동한다.

C++ Vision Bridge: N/A.

Demo Operation: N/A — 신규 Demo 또는 제품 기능 설명은 없다.

Audience Interaction: Q&A 3분은 선택적 질문 시간이다. 답변이나 공유를 강제하지 않는다. 침묵은 정상적인 결과로 둔다.

Transition: “방금 떠올린 원하는 결과를 작업 요청으로 전달하려면 무엇이 더 필요할까요?”라는 질문으로 `Chatbot → Prompt`를 handoff한다. ACT 1의 내부 구조는 소개하지 않는다.

Time Management: Slide Map의 순서를 유지해 Transition 3분 뒤 Q&A 3분을 둔다. Q&A를 늘려 ACT 전체 시간을 옮기지 않는다.

Fallback: 질문이 없으면 Opening Question을 그대로 남기고 종료 cue로 ACT 1에 넘긴다. 강사가 질문에 답을 보태지 않는다.
